# 任务 B：语音转文字与照片识字

先读 [团队入口](README.md) 和 [接口草案](MEDIA-CONTRACT.md)。你交付的结果是：给一个已保存的文件，返回真实识别文字或清楚、可恢复的失败。你不负责上传、数据库、Event 生成或前端页面。

## 开工先核对

- 阅读 `backend/adapter.py`、`backend/safety.py`、`.env.example`、`requirements*.txt`、`docs/VALIDATION.md`。现有 adapter 是文本整理，不能把它宣称为媒体识别。
- 按 AGENTS.md 恢复项目，先说明自己的工作范围、已有能力、未知项和执行路线，确认后开发；建议分支 `feat/media-recognition`。
- 核查实际可用服务、语言／格式支持、文件／时长限制、超时、配额与费用。环境变量仅检查是否设置，不输出值；不上传 `.env`、数据库、模型缓存或依赖目录。
- 先与 A 对齐函数签名和失败结构。可以用独立临时文件验证模块，无需等待前端或上传 API。

## 必须交付

| 编号 | 需求与通过标准 |
|---|---|
| B1 | 一个真实 ASR 接入：中文短录音返回文字，成功与超时／失败都有证据。不得把固定样例、浏览器已有文本或整理模型输出冒充真实转写。 |
| B2 | 一个真实 OCR 接入：清楚的印刷资料照片返回文字，成功与失败都有证据。先不承诺手写、所有口音、复杂版式或所有噪声环境。 |
| B3 | 使用统一函数输入／输出，见接口草案。已保存原件只读；有必要的转码只生成派生文件并检查未截断，不能替换或删除原件。 |
| B4 | 保留原始识别初稿。药名、数值、单位、日期不猜补，不加入自动润色纠错层。无可靠不确定性字段时明确缺失，不能编造置信分数。 |
| B5 | 空文字、无法辨认、损坏、格式不支持、时长或大小超限、鉴权失败、限流、网络失败、服务超时、非法响应分别有稳定错误码与可重试建议。公开消息不包含密钥、服务原始错误正文或文件绝对路径。 |
| B6 | Mock 与真实服务显式分开。未配置真实服务返回清楚的未配置状态，不静默回退 Mock；选择 Mock 时结果与证据都标注模拟。 |
| B7 | 调用有超时、资源与并发边界，不加入无限重试或多层重试。识别重试由 A 的任务接口控制；服务调用可能重复收费的边界如实记录，不声称跨第三方 exactly-once。 |
| B8 | 提供部署前置条件和能力清单：服务／模型、配置变量名称、必要工具或依赖、格式与限制、数据去向、费用条件、实测耗时、失败处理。不输出密钥值，不擅自购买或开通服务。 |

## 先做的小样与可继续工作

确认可使用的服务及脱敏资料后，用一段真实录音和一张清晰照片验证服务确实能返回文字，再扩大接线。优先复用团队已有可用能力；无可用服务时仍可完成函数、明确标记的 Mock、错误处理和模块测试，真实成功项保留未验证并向负责人报告阻塞。

先采用单文件识别。流式音频、说话人分离、声纹、自动纠错和复杂模型编排不在当前默认实现中。录音行为已确认“长时间没声音先提醒，提醒后仍无回应再自动暂停，保留内容并可接着说”。具体静音时长、提醒后等待时长及检测方式仍需真机验证小声、停顿、电视噪声；B 提供能力和局限，不用普通响度判断承诺可靠识别所有场景。自动暂停不等于上传成功或记录已核对。

录音时长、大小及格式限制以实测服务能力和后续确认的合同为准。60 秒要求已经撤回，不能把它作为默认值或拒收条件。若服务无法接受某种录音，应保留原件并交由 A 返回清楚状态，不能悄悄截短送识别。

## 最小验证清单

- [ ] 真实录音识别成功，人工对照原话记录错字和遗漏，不把一条通过解释为全口音覆盖。
- [ ] 清楚照片 OCR 成功，对照药名、数值、单位、日期，原图模糊处不猜写。
- [ ] 超时、网络失败、限流、鉴权失败、空结果、非法响应均有稳定错误分类，且不泄露服务正文或密钥。
- [ ] 支持格式实测；格式伪装、损坏文件、超限和转码截断被发现，原件未变。
- [ ] 危险描述样例能将实际识别文字交给 A 扫描；如误识别导致未命中，如实记录失败，不能算安全通过。
- [ ] Mock 和真实调用分别可复现、可辨认；未配置真实服务不会静默模拟。
- [ ] 与 A 联调：识别失败原件仍在，重试不重复 Event，重启恢复，整理 422 仍保留文字和原件。

## PR 应交给别人什么

1. 独立识别模块与针对成功／失败的模块测试。避免直接改 `backend/server.py`、`backend/store.py`、现有文本 `adapter.py`。
2. `docs/team/HANDOFF-B.md`：基线及验证提交、函数用法、服务／模型、配置变量名称、依赖变更建议、实测支持范围、耗时、错误码、已知限制、待解决事项、依赖的 PR。
3. `docs/evidence/media-b/`：脱敏真实服务成功与失败证据，记录日期、服务／模型、样例来源与使用许可、输入校验和、识别结果或脱敏摘录、人工对照、测试方式及结果。只提交有权公开的样例；获准测试不等于获准公开原件。
4. 把必要依赖和环境变量的变更清单交给 A 收口，避免两人同时修改共用文件；按 [合并指南](INTEGRATION.md) 推分支开 PR。
