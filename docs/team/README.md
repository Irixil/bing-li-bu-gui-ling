# 两人后端开发入口

更新于 2026-09-12。本页和两份任务单是项目负责人要求发布的协作需求，不代表媒体功能已经实现，也不代表下面标为“建议／待定”的实现方案已经获准。

## 新同学只需做什么

1. 使用 Git 克隆仓库，在 Codex 中打开克隆目录。建议不要下载 ZIP，Git 克隆才能方便更新、推送分支和发起 PR。
2. 选任务 A 或任务 B，把下面对应的一句话发给 Codex。
3. Codex 先核对当前仓库，说明要交付什么、还有什么没定、准备怎么做；你确认执行路线后，在自己的分支开发。

**任务 A 的开场话**

> 我负责本仓库的任务 A：媒体文件、持久化、状态和 API。请先读取 AGENTS.md、PROJECT.md、docs/team/README.md、docs/team/TASK-A-MEDIA.md 和 docs/team/MEDIA-CONTRACT.md，按仓库恢复流程只读核对 Git、代码、需求和已有证据，用大白话告诉我负责什么、如何与任务 B 配合、先做哪一步。等我确认路线后再写代码。不要接管老人端前端，不要恢复已撤回的 60 秒规则。

**任务 B 的开场话**

> 我负责本仓库的任务 B：语音转文字和照片识字。请先读取 AGENTS.md、PROJECT.md、docs/team/README.md、docs/team/TASK-B-RECOGNITION.md 和 docs/team/MEDIA-CONTRACT.md，按仓库恢复流程只读核对 Git、代码、可用识别服务和已有证据，用大白话告诉我负责什么、如何与任务 A 配合、先做哪一步。等我确认路线后再写代码。不要修改数据库和老人端前端，不要恢复已撤回的 60 秒规则。不要读取或输出密钥值，也不要擅自开通付费服务。

Codex 若未安装 DZ 技能，应如实告知，先完成仓库文档与代码的只读分析。不要伪造 resume-report 或把旧下一步当成命令；由使用者决定安装技能或明确采用的替代流程。没有该技能也能阅读这两份任务单、了解分工。

## 已确定的需求

- 老人自己使用，主要通过语音、拍照记录，打字补充；比赛 MVP。前端由项目负责人负责，两位后端同学不增加子女端、医生账号、支付、多租户或公网生产部署。
- 一段录音／一张清楚的印刷资料照片，先持久化原件，再识别中文文字，保留机器初稿与人工修改，关联现有 Event，接上整理、核对、修订、历史、就诊材料。
- 上传被后端确认成功以后，刷新、识别失败、进程重启都不能让原件消失。原件未保存成功不能显示“已保存”。
- 上传重试、识别重试和 Event 生成不能重复；版本冲突必须返回 409，不能强行覆盖。
- “原件已保存”“文字识别完成”“记录已核对”分别表达。只有人工明确核对才可标记记录准确，识别成功不能自动核对。
- 药名、数值、单位、日期不猜写。没有可靠字段就不编造置信分数或逐字不确定标注。
- 识别文字一出现就执行本地危险扫描，先于后续整理；识别失败时不能宣称完成文字危险检查。已经命中的提醒不得因核对而消失。
- 详情能查看原件，修订不切断来源，交接快照能说明来源和待核对状态；原件和数据库一并备份、恢复。
- 只使用合成或明确允许的脱敏样例；真实识别与 Mock 的结果分别标注。
- 录音长时间没有声音时先提醒，提醒后仍无回应再自动暂停；保留已录内容，允许接着说。自动暂停不是上传成功，也不是核对完成。前端负责操作体验，后端与识别同学配合文件与状态衔接。

## 已撤回和待确认

**“从开始录音起最长 60 秒自动结束”已被用户明确撤回。** 不得把 60 秒写成默认录音时长、后端拒收阈值、验收条件或隐含配置默认值。

| 待定项 | 谁协调 | 当前可以做什么 |
|---|---|---|
| 已选“提醒后无回应再暂停”；具体静音时长、提醒后等待时长、检测方法与暂停续录的文件交接 | 项目负责人与前端协调，A/B 提供能力限制 | 真机验证小声、停顿、电视噪声后确定参数；不得改成强制结束，续录不得丢前段 |
| ASR/OCR 服务、已有权限、成本和数据传输范围 | B 核查，项目负责人确认涉及外传或费用的选择 | 先查公开文档和已有配置名称，不读取、打印或提交密钥值；可先做明确标记的 Mock |
| 音频时长、大小、编码；图片格式、大小、像素上限 | A 汇总 B 的服务限制，与前端及项目负责人确认 | 制定有界校验方案、准备参数化测试；具体生产默认值尚未确定 |
| HTTP 字段、识别函数、重试协议和合并方案 | A 收口，B 和前端核对 | 以接口草案讨论；代码接线前冻结实际合同 |

上一轮建议的 10 MiB、2000 万像素等数值也未被确认。不能为了绕过待定项而接受无限大的上传；实际媒体入口启用前必须公布并验证限制。产品录音策略和第三方服务上限是两回事，冲突时提出选择，不能暗中截断原件。

## 当前代码基线与证据

文档准备时主仓库和 GitHub main 均为 `e1a5967`，工作区干净；每位同学开始时重新核对，不能假定以后仍是这个提交。

已有文本保存、SQLite、有限危险规则、整理（默认 Mock）、核对、修订、历史、幂等、版本冲突和交接快照。`source_kind=audio_transcript/document` 只是文本来源标签。还没有文件上传、媒体保存读取、ASR/OCR、媒体处理状态；`scripts/backup.py` 只备份数据库。

历史证据为 71 项后端测试、40 条合成回归、1 位公开病例的 3 段摘要和进程重启测试；不是本次媒体、真实服务或临床验收。详见 [VALIDATION.md](../VALIDATION.md)。主仓库当时没有 `.env`，当前任务环境没有发现可用识别凭据，不代表其他同学一定没有。

## 从分支到一个可运行项目

详细命令和验收见 [INTEGRATION.md](INTEGRATION.md)。推荐顺序：

1. A 先提交最小合同 PR，B 与前端确认函数、状态、字段和错误含义；标注哪些已实现、哪些未实现。
2. A 做保存、恢复、幂等和 API；B 用本地临时文件及测试替身独立开发识别，不必等待上传页面。
3. B 的识别模块与 A 的保存底座分别发 PR；A 负责最终调用接线。按合同兼容性决定先后，不能让 main 出现缺失导入或未安装依赖。
4. 合并后用同一个提交完成媒体成功、失败、重启、冲突、危险提醒、422、备份恢复与手机联调；失败项保持未完成。

所有权用于减少冲突，不是禁止修问题。跨负责人文件先在 PR 说明并协调；不要在合并时顺手重写另一人的业务。

## 需求如何更新

两份任务单是这一轮的工作要求；[MEDIA-CONTRACT.md](MEDIA-CONTRACT.md) 是尚未冻结的实现草案；[API.md](../API.md) 和 [contracts/api.ts](../../contracts/api.ts) 仍描述当前已实现合同。不要让草案冒充正在运行的接口。

新的产品选择由项目负责人确认后更新本目录，并记录确认来源。每人可以在自己分支用 DZ 工具记录当前进度，但 `.dz/journal.jsonl` 的两条分支历史不能机械拼接；由集成人核对后用状态工具逐项重录必要记录，重新生成 PROJECT.md 等视图。不要手改、强选一边覆盖或虚构 accepted/verified 状态。

本轮授权是编写并发布协作需求。两位同学开工时仍须确认各自的当前工作区和执行路线；文档不是无人值守写代码、付费、外传资料或上线的通行证。
