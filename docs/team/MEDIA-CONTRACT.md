# 媒体接口协作草案 v0

状态：**待 A、B 与前端对齐，尚未实现、尚未冻结**。本文件给两人一个共同起点；字段或端点在实际合同 PR 合并前都不能宣称已可调用。当前可用 API 仍以 [API.md](../API.md) 和 [api.ts](../../contracts/api.ts) 为准。

## 不变的行为与未定参数

原件先持久化，识别失败保留原件；成功产生文字后立刻扫描危险描述，先于整理；机器初稿、人工修订和原件可追溯；不重复生成 Event；核对不清除危险提醒。

前端已确认录音“长时间没声音先提醒，无回应再暂停，保留内容并可接着说”。静音时长、提醒后等待时长、检测方法待真机验证；60 秒强制结束已撤回。暂停／续录属于采集状态，不能映射成媒体已保存或 Event 已核对。

格式、时长、字节及像素上限没有确认值。A/B 依据服务和设备证据提出能力表，前端与负责人确认后写进正式合同；入口启用前必须有有限且实测的边界，不使用隐藏默认值。暂停续录产物是否需合成由前端与 A 明确，不能丢前段、不能悄悄分成多条 Event。

## 拟定 HTTP 接口（A 收口）

| 接口 | 作用 | 必须表达 |
|---|---|---|
| `POST /api/media` | 单文件上传 | 有界二进制／multipart 形式待选；不要默认把大文件塞进现有 JSON body。上传幂等键、媒体种类、返回媒体对象和 `created`；确认持久化后才能成功 |
| `GET /api/media` | 恢复上传列表 | 包含没有 Event 的保存成功、处理中和失败项；支持有限返回／分页方案，不能只从 Event 反查 |
| `GET /api/media/{id}` | 查状态与关联 | 保存状态、识别状态、版本、尝试、可公开失败原因、文字与 Event 引用 |
| `GET /api/media/{id}/original` | 播放／查看原件 | 正确 Content-Type、读取权限边界、必要的 Range 行为；不暴露任意路径，不将 token 放 URL |
| `POST /api/media/{id}/recognize` | 开始识别或明确重试 | `expected_version`、识别幂等键；已成功则返回现有关联，处理中返回同一尝试，不重复开任务；失败后新重试键创建下一次尝试 |

建议上传首次成功 201、幂等重放 200，识别启动 202 后按详情查询，冲突 409，非法类型 415、大小超限 413；最终状态码在合同 PR 中固定。具体执行可先用本机进程中的有限工作线程，不预引入外部队列；进程重启必须能恢复可重试状态。

现有 JSON 写接口仍使用 `/health` session_token 和 `X-Session-Token`。新上传的 Content-Type 和 CORS headers 单独约定。媒体读取需明确本地访问规则和浏览器播放器如何携带凭据，不能在原件 URL 中放会话 token。继续保留本机单人运行边界，不假定 `/api/auth/*` 已提供公网家庭隔离。

## 建议数据字段与责任

| 对象 | 建议字段 | 谁写入 |
|---|---|---|
| 媒体 | `media_id`、`kind`、`content_type`、`size_bytes`、`sha256`、`saved_at`、`version`、原件引用 | A |
| 识别尝试 | `attempt_id`、`status`、开始／结束时间、`provider`、`model`、`is_mock`、失败结构、完整机器初稿 | A 持久化 B 的结果 |
| 来源关联 | 媒体 ID、所选尝试 ID、初始 Event ID、后续修订来源关系 | A，数据库约束防重复 |
| 文字安全检查 | 是否已扫描、扫描用的文字版本、本地规则结果、历史已命中提醒 | A，识别无文字时标明尚无可扫描文字 |
| 人工核对 | 沿用 Event 状态、版本及修订历史 | 现有 Event 流程；媒体识别不得自动改为 recorded |

Event 创建必需字段也要在合同中明确：建议录音使用 `source_kind=audio_transcript`，照片使用 `document`；`actor_name` 由哪个请求字段或已确认身份取得需要写明，不能把服务商或模型当成记录者。发生时间不确定则保留空值，记录时间由服务器给出。照片里有日期也不能未经核对就当作本次症状发生时间。以上映射由 A 在合同 PR 收口，B 不自行构造 Event。

建议识别状态为 `not_started / processing / succeeded / failed`。`succeeded` 只表示保留了有效识别文字；若文字超过现有 Event 10000 字符限制，可有文字但尚未生成 Event，需单独表达关联结果与原因，不能截断文字或称全部记录成功。空识别结果不伪造“用户没事”或空 Event。

文件以服务端生成的 ID 存在专用目录，数据库存可恢复的相对引用；不把原文件名当路径。建议原件不可变；所有上传、验证、识别、关联及恢复的部分失败要明确如何处理临时文件和悬空引用。数据库提交与文件落盘不是同一事务，需要测试崩溃窗口，不能只靠“先写文件再插表”声称不会丢。

## A 与 B 的函数边界

建议一个简单模块 `backend/recognition.py`；本例是签名讨论稿，不要求复制到代码，不是新增通用框架。

```python
def recognize_file(path, *, kind, content_type, attempt_id):
    """只读已保存的本地文件；返回成功结果，或抛出分类错误。"""
```

成功结果必须含 `text`、`provider`、`model`（服务未给出时可空）、`is_mock`。可以返回有可靠来源的警告／不确定信息；没有可靠来源就不伪造字段。错误至少包含稳定 `code`、安全的 `message`、`retryable`；不能把服务原始正文或密钥透传前端。B 负责底层超时与资源约束，A 负责任务状态和重试调度，两层不能重复无限重试。

错误码建议涵盖 `provider_not_configured`、`unsupported_format`、`invalid_media`、`limit_exceeded`、`no_text_detected`、`provider_timeout`、`provider_unavailable`、`provider_auth_failed`、`provider_rate_limited`、`invalid_provider_response`。A 另处理 `processing_interrupted`、保存／关联失败。自动化测试需有确定的成功和错误替身；真实服务验收另列。

B 不持有数据库对象、不创建 Event、不启动 HTTP 请求处理器；A 不重复写一个 ASR/OCR 适配器。A 调用成功后马上扫描文字，先持久化完整初稿与安全结果；随后在一致事务中创建唯一 Event 并写入关联。Event 校验／关联失败不能回滚已保存的识别文字，应单独保存关联失败原因。文字落库本身失败时不得返回“文字已保存”，原件仍可找回。

已保存文字但未生成 Event 时，要有明确的关联恢复入口，复用本次初稿并检查版本，不重新请求识别服务；端点或 recognize 的幂等恢复语义由合同 PR 明确。超长文字的产品处理尚未决定，不能用截断代替恢复。关联成功后普通重放只返回同一 Event。

## 重试、版本与来源约束

- 上传同一键同一内容返回原媒体；同键内容改变返回 409。相同文件作为用户新记录提交新键，可保留为另一份输入，不能仅按 hash 吞掉用户的新动作。
- 识别尝试有持久化占用与版本。处理中重复请求返回原尝试；失败后显式重试；成功后普通重试返回已有结果，不默认重新计费识别。
- 丢失响应后重放必须优先找到原结果，再判断当前版本；不能把客户端不知道已成功的重试当新操作。旧尝试迟到，不能覆盖新尝试和人工改错。
- Event 唯一生成和媒体关联由后端保证。后续人工修订继续沿用 `expected_version` 和来源链；不修改机器初稿、不丢原件、不继承“已核对”状态。
- 第三方是否计费／幂等不可假定。重启导致外部调用结果未知时如实记录，先恢复到可重试状态，不无条件自动重提。
- 未命中只表示已扫描文字未被有限规则命中；没有文字则根本未完成这一步。历史命中的危险提醒在核对及查看修订来源时仍可见。
