# 任务 A：原件、持久化、状态与 API

先读 [团队入口](README.md) 和 [接口草案](MEDIA-CONTRACT.md)。你交付的结果是：老人上传的录音／照片存得住、找得到、可以重试，识别后能接回现有记录流程。你不负责选择识别模型，也不开发前端页面。

## 开工先核对

- 阅读 `backend/server.py`、`backend/store.py`、`scripts/backup.py`、`docs/API.md`、`contracts/api.ts`、`tests/test_persistence.py`、`tests/test_offline_safety.py`、`tests/test_backup.py`，实际追踪 create/revise/history/handoff 和事务边界。
- 按 AGENTS.md 恢复当前项目，报告已有内容、后来变化、未知项和本人的执行路线。确认后创建自己的分支，建议 `feat/media-storage-api`。
- 与 B 对齐识别函数的输入、输出和错误，再把前端可用的 HTTP 合同交给项目负责人。先给出合同 PR，不让 B 等完整上传功能才开工。

## 必须交付

| 编号 | 需求与通过标准 |
|---|---|
| A1 | 上传原件先持久化。媒体 ID、内容校验和、真实类型、大小、保存时间和相对存储引用入库；原件与元数据一致后才返回已保存。失败不得产生假成功。文件名不能成为任意读写路径，拒绝伪造类型和越界请求。 |
| A2 | 媒体列表、详情、原件读取／播放入口。未生成 Event 的上传和失败任务也能刷新找回；读取不泄露磁盘绝对路径、凭据或其他文件。播放需在约定浏览器验证，必要时支持 Range。 |
| A3 | 保存状态与识别状态分开持久化；记录识别尝试、可公开的失败原因、是否可重试及服务类型。服务中断后，处理中任务可找回并明确转成可重试，不可永久卡住。 |
| A4 | 上传幂等、识别单次占用／重复请求去重、Event 唯一关联。响应丢失后同键同内容返回原结果；同键不同内容返回 409。成功重试不能新建第二个 Event，迟到结果不能覆盖新尝试或人工改错。 |
| A5 | 机器初稿不可被人工修订覆盖；原件、识别尝试、初始 Event 和后续修订可追溯。保持 expected_version；冲突返回 409，不能自动重试成强制覆盖。不要客户端用普通 create 绕过媒体唯一关联。 |
| A6 | 调用 B 的识别函数后立即扫描文字危险描述，先于整理。扫描结果与文字持久化；核对不能清掉提醒。修订后的详情也能看见来源初稿曾命中的提醒，不能仅因主列表隐藏旧版本而让提醒不可见。 |
| A7 | 详情包含来源，交接快照包含来源和待核对信息；未产生 Event 的失败媒体也不能从交接准备中悄悄消失，可列为尚无可用文字的附件，不得伪造医学摘要。后续修订不改变旧快照。 |
| A8 | 数据库与全部被引用原件一并备份，恢复到新目录后链接可用，校验文件缺失／损坏。使用一致快照或短暂暂停写入，避免数据库已引用但附件未复制。旧数据库升级有安全步骤并验证原文本记录仍可读。 |
| A9 | 同步实际 API、TypeScript 类型、启动／恢复说明及前端调用示例。只沿用本机单人 session 合同，账号兼容路径后置；新增媒体读取的边界要写明，不能包装成已具备公网安全隔离。 |

## 与 B 的边界

B 只拿到已保存的本地文件和必要元数据，返回识别文字或结构化失败；B 不开数据库、不创建 Event、不修改 HTTP 响应。A 负责占用任务、调用、超时外围处理、安全扫描、先保存识别结果，再原子创建／关联 Event，以及前端状态恢复。Event 失败不能回滚初稿；恢复关联复用已保存文字，不重新调用识别服务。A 在合同中写明 actor_name、来源类型、发生时间等必填／可选字段来源。

现有 `raw_text` 最多 10000 字符。OCR 或 ASR 超过它时，必须保留完整识别初稿，明确提示尚未生成 Event；不能截断后声称成功。分段／选择文本等产品处理方式需要明确约定，不能扩大这轮默认范围。

录音行为已确认“长时间没声音先提醒，无回应再自动暂停，保留内容并能接着说”；静音时长、提醒后等待时长和检测方法仍待真机验证。自动暂停不代表上传成功或核对完成。A 与前端约定暂停续录如何交付完整录音，验证前后内容都在，不擅自引入分段 Event 或改变用户流程。

数值限制仍待定，尤其不能加入已撤回的 60 秒限制。可先做校验机制与参数化测试；媒体入口启用前由 A 汇总并公布确认后的限制与能力，前端应据此提示。超限或解码失败不应悄悄截短已保存原件。

## 最小验证清单

- [ ] 同一上传并发／丢响应重试只产生一个媒体对象，同键不同内容 409。
- [ ] 原件写入失败、数据库失败没有“已保存”假结果；中断后可解释地恢复，重试不会产生冲突残留。
- [ ] 超时、网络失败、空文字、服务异常：原件可读，状态与原因刷新、重启后仍可查。
- [ ] 重复识别、并发识别、处理中重启、迟到结果不重复建 Event、不覆盖人工修订。
- [ ] 人工改错后初稿与原件仍可查看；版本冲突不覆盖；危险描述提醒在核对后仍在。
- [ ] 整理返回 422 时原件、文字和已有危险提醒仍在。
- [ ] 备份恢复到空目录，校验原件内容、关联、文字、状态与交接快照；旧文本数据库升级不丢数据。
- [ ] 无 Event 的失败媒体能在列表和交接准备中找到；超长文字完整保留。
- [ ] 有界上传、真实类型校验、路径穿越、原件访问边界及播放路径通过验证。
- [ ] 与前端联调暂停后接着说，交付的录音前后内容均保留；暂停状态、上传成功和人工核对不混淆。

证据放 `docs/evidence/media-a/`，仅提交脱敏测试结果与可复现说明。自造替身必须标明 Mock；真实录音和照片验收由 A/B 联合补齐。不能仅凭 HTTP 200 判定内容正确。

## PR 应交给别人什么

1. 文件与状态功能、必要迁移和恢复工具、可重复的测试。
2. 更新的 API/类型合同与可执行调用示例，明确 B 函数接口版本和前端接法。
3. `docs/team/HANDOFF-A.md`：基线及验证提交、改了什么、如何启动和恢复、实际支持范围、测试命令与结果、证据路径、已知限制、依赖哪个 PR、下一位接什么。不粘贴 token、真实记录或数据库。
4. 按 [合并指南](INTEGRATION.md) 推自己的分支并开 PR。不要直接推 main，不要在不理解冲突时选“全部采用我的”。
