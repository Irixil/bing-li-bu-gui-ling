# 病历不归零·内测版：第一版功能约定（本地优先修订草案）

## 1. 这是什么

这是一个面向真实使用的私密健康记录内测版。使用者用文字、录音或照片留下原始资料，AI 只生成待核对草稿，人工确认后形成可查找、可修订、可备份、可用于就诊沟通的连续记录。

第一版采用“本地优先”：健康记录、修订历史和媒体原件的日常主副本加密保存在使用者选定的主设备浏览器中；veFaaS 负责在线页面、访问保护和按次 AI 转发，不长期保存健康资料明文；使用者启用云备份后，浏览器先加密备份，再把密文保存到私有 TOS Bucket。电脑不需要为手机访问而保持开机。

第一位试用者是项目所有者本人。产品展示名统一为“病历不归零·内测版”；用户界面、启动说明和主 README 不再把它称为比赛产品或 Demo。比赛材料可保留在历史文档中，不得继续控制产品主线。

## 2. 第一版怎么用

1. 使用者从自己的手机或电脑浏览器打开 veFaaS 内测地址，通过所有者访问保护进入，并在一台设备上建立加密的本地主数据。
2. 首页可直接选择说一段、拍一张或写一段。
3. 原话或原件先保存，页面再发起识别和整理。保存、识别、整理和核对是不同状态。
4. AI 结果清楚标成待核对草稿。使用者可以确认、退回或修订，原始资料一直可查。
5. 确认后的记录进入当前设备的时间线，可按关键词、日期、类型和状态查找。
6. 就诊前选择日期范围和记录，生成可预览、打印或导出的就诊材料。
7. 设置里可查看本机存储占用、AI 连接、数据外发边界、最近备份、换机恢复和本地内测反馈。

- [DZ-MUST:R2] 使用者能通过文字、浏览器真实录音和真实照片创建记录，并在任何 AI 处理前看到原话或原件已经加密保存到当前设备的明确状态。

## 4. 关键状态和恢复

- **还没有记录**：说明三种录入方式，不显示虚构示例为本人数据。
- **正在保存或上传**：防止重复提交，断网后保留未提交输入，恢复后使用同一次幂等请求续传。
- **正在识别或整理**：页面可离开，返回后能重新读取持久化状态。
- **AI 失败**：原话或原件仍可查看，可手工补充、显式重试或稍后继续。重试要显示会再次调用外部 AI。
- **旧草稿存在但新整理失败**：旧草稿明确标为旧版，不冒充本次成功。
- **版本冲突**：先读取最新版本，保留本次输入，让使用者选择重新修订，不静默覆盖。
- **会话失效或断开**：清楚说明需重新进入，不把本地访问错误说成 AI 失败。
- **删除**：先展示将删除的记录、原件和关联影响，再二次确认；删除失败时不显示成已删除。
- **本机空间不足**：停止新增大文件并保留尚未提交的输入，展示占用和清理选择，不自动删除原件。
- **备份失败**：本地数据继续可用，页面保持“未备份”状态，说明网络、权限、额度或校验原因，不把排队上传显示成成功。
- **备份恢复**：先在新设备本地验证密文、解密和完整性并预览条数和媒体数量；恢复到隔离位置验证通过后，才能明确选择替换当前数据。
- **恢复密钥丢失**：明确说明云端密文无法解密，不提供绕过或虚假的找回承诺；当前仍能解锁的旧设备可以创建使用新密钥的新备份。

## 5. 数据、AI、权限和费用边界

- 记录、修订历史、审计状态、媒体原件和内测反馈默认加密保存在当前主设备的浏览器存储中；不同设备默认没有自动同步。
- veFaaS 长期保存应用代码、非敏感运行配置和访问保护信息，不把函数临时目录当作病历数据库或媒体盘。
- 启用云备份后，浏览器在上传前完成加密；TOS 保存密文对象和最小必要的非健康元数据。恢复密钥不发送给 veFaaS、TOS、DeepSeek 或 AIHubMix。
- 备份使用短时、限路径的上传或下载授权；浏览器和页面不接触火山引擎长期 AK/SK。
- 用户选择在线整理时，该条必要文字证据会发给 DeepSeek；选择在线识别时，该份录音或照片会发给 AIHubMix 及它代理的上游模型服务。
- 当前未取得可绑定本版的服务商数据留存、人工查看或模型训练保证；页面保留这项未验证说明，不默认做否定性承诺。
- 使用者可关闭在线 AI，继续保存原件、手工录入识别文字和手工整理。
- 页面不读取、显示或导出 API 密钥；日志、反馈和备份也不包含 API 密钥。恢复密钥只由使用者保管，丢失后云端密文无法恢复。
- 只有使用者主动发起识别、整理或显式重试才会产生付费 AI 请求。本版不在后台轮询时重复计费，不自动换付费模型。
- veFaaS、APIG 和 TOS 可能按实际使用产生费用；页面不承诺固定免费，部署验收记录实际资源和费用开关。
- 删除只能证明内测环境本地副本被删除；不在没有服务商证据时承诺已删除对方曾处理的数据。
- 如果旧加密备份仍包含已删除记录，页面会明确提示，并提供清除旧备份后重新生成干净备份的动作；不把只删除当前设备说成所有副本都已删除。

## 6. 以后再看

- 家属、照护者和医护的多角色协作。
- 公网注册、多人账号、组织隔离、支付和订阅。
- 实时跨设备同步、合并冲突和家庭共享。第一版只支持加密备份后在另一设备恢复。
- 提醒计划、药物库、医院系统或穿戴设备对接。
- 复杂医学影像解读，包括 CT、MRI、X 光或病理图像的诊断性分析。
- 自动对外发送就诊材料。

## 7. 明确不做

- 不诊断疾病，不预测病情，不自动改药或生成个人化用药建议。
- 不把 AI 输出写成医生意见，不把本地规则未命中写成医学正常。
- 不代替急救服务或专业医疗判断。
- 不自动发送、发布、分享或购买任何外部服务。
- 不把比赛任务分工、演示话术或人造样例放在使用者主界面。

## 8. 第一版怎样算通过

1. 所有者能从目标手机浏览器进入，未授权浏览器不能使用在线服务，未解锁设备不能读取本地健康资料；电脑关机不影响手机访问。
2. 一条文字记录能完成保存、真实 AI 整理、核对、查找和修订。
3. 一段目标浏览器录制的真实 WebM/实际媒体格式能完成原件保存、真实识别、安全扫描和记录关联。
4. 一张目标手机拍摄的真实照片能完成同样的保存、识别和关联流程。
5. 分别演练断网、AI 超时/失败、权限拒绝、重启和版本冲突，确认原始资料不丢、页面不虚假报成功且有恢复动作。
6. 用至少六条不同日期和类型的合成或打码记录，验证时间线查找、筛选、历史、选取交接和 PDF 导出。
7. 在浏览器端创建一份不含 API 密钥和恢复密钥的加密备份，下载一份并向私有 TOS 上传一份；在全新浏览器资料目录中完成解密、完整性检查、隔离恢复和数据/原件对比，再演练一次有预览的替换恢复。
8. 在关闭在线 AI 后，仍能保存原件和手工完成记录；重新开启前页面会再次告知数据外发对象。
9. 删除一条专用测试记录时先看到影响预览；确认后记录和关联本地原件不再可读，其他记录不受影响。
10. 所有者从真实使用页面保存一条内测反馈，反馈不含健康原文、媒体或 API 密钥。
11. 关闭电脑后，目标手机仍能打开 veFaaS 页面、解锁本地数据并完成不需要在线 AI 的操作；断网时新增内容先保存在本机，联网后由使用者确认备份。
12. 在另一浏览器打开应用时不会虚假出现主设备数据；使用加密备份恢复后才出现相同记录，并能识别备份版本和来源设备。

## 9. 当前带着的未确定性

- veFaaS 已有账号、两个 DeepWe 应用和一个 APIG 网关可用，但“病历不归零”独立应用和私有 TOS Bucket 尚未创建；不得覆盖现有 DeepWe 应用。
- AIHubMix 和 DeepSeek 对这一具体 API 使用方式的留存、人工查看和训练政策尚未取得可验证结论；这会在内测页面明示，真实敏感内容是否外发由所有者决定。
- 现有录音只有合成 WAV 真实识别成功证据，浏览器 WebM 和目标手机必须重新验收。
- 目标手机浏览器能否授予持久存储、实际配额和清理策略必须实机验收；浏览器本地存储不能被描述为永不丢失。
- TOS Bucket 权限、跨域规则、短时上传授权、备份保留规则和实际费用尚未配置，创建或产生费用前需要单独确认资源范围。
