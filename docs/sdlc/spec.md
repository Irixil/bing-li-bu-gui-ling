# 病历不归零·内测版：第一版功能约定（草案）

## 1. 这是什么

这是一个面向真实使用的私密健康记录内测版。使用者用文字、录音或照片留下原始资料，AI 只生成待核对草稿，人工确认后形成可查找、可修订、可备份、可用于就诊沟通的连续记录。

第一位试用者是项目所有者本人。产品展示名统一为“病历不归零·内测版”；用户界面、启动说明和主 README 不再把它称为比赛产品或 Demo。比赛材料可保留在历史文档中，不得继续控制产品主线。

## 2. 第一版怎么用

1. 使用者从自己的手机或电脑浏览器打开私有内测地址，通过所有者访问保护进入。
2. 首页可直接选择说一段、拍一张或写一段。
3. 原话或原件先保存，页面再发起识别和整理。保存、识别、整理和核对是不同状态。
4. AI 结果清楚标成待核对草稿。使用者可以确认、退回或修订，原始资料一直可查。
5. 确认后的记录进入时间线，可按关键词、日期、类型和状态查找。
6. 就诊前选择日期范围和记录，生成可预览、打印或导出的就诊材料。
7. 设置里可查看本机存储、AI 连接、数据外发边界、备份恢复和本地内测反馈。

## 3. 这次必须做到

- [DZ-MUST:R1] 使用者能在手机和电脑的受支持浏览器中打开“病历不归零·内测版”，未通过所有者访问保护的人不能读取或修改健康资料。
- [DZ-MUST:R2] 使用者能通过文字、浏览器真实录音和真实照片创建记录，并在任何 AI 处理前看到原话或原件已保存的明确状态。
- [DZ-MUST:R3] 录音和照片在真实 AI 服务中成功识别后才显示识别文字；处理中、失败、超时、断网、权限拒绝和额度问题都有明确说明，失败不删除原件，付费 AI 请求不自动重试。
- [DZ-MUST:R4] AI 整理结果始终显示为待核对草稿，使用者能对照原始资料确认、退回或修订；确认只表示记录准确，不表示医生确认、诊断或风险消失。
- [DZ-MUST:R5] 使用者能在连续时间线中按关键词、日期范围、记录类型和处理状态查找记录，并查看原话、原件、AI 草稿、当前状态和修订历史。
- [DZ-MUST:R6] 使用者能通过保留历史的方式修订记录，也能在看到具体影响并二次确认后删除选中的记录及其本地原件；删除不得连带其他记录或密钥。
- [DZ-MUST:R7] 使用者能选择日期范围和记录生成就诊材料，预览中保留原话、来源、未确定时间、待处理项和安全提醒，并能使用浏览器打印或导出 PDF，不自动对外分享。
- [DZ-MUST:R8] 使用者能创建包含数据库和媒体原件、不包含 API 密钥的一致性备份，并在不静默覆盖现有数据的前提下预览、恢复和验证该备份。
- [DZ-MUST:R9] 页面在空数据、加载、保存中、上传中、AI 处理中、待核对、断网、重启、会话失效、局部失败和恢复后都给出真实状态和可继续动作，不将“已接受”、“处理中”或旧草稿显示成本次成功。
- [DZ-MUST:R10] 在首次使用真实 AI 前，页面明确说明选中的文字会发给 DeepSeek，选中的录音或照片会发给 AIHubMix 及其上游模型服务；使用者可以不同意外发而继续本地保存和手工整理，页面不宣称未经核实的服务商保留或训练政策。
- [DZ-MUST:R11] 本地危险提醒和专业复核线索在保存、AI 失败、核对、修订、时间线、就诊材料和备份恢复后都不被静默清除；未命中规则不显示成“正常”或“无风险”。
- [DZ-MUST:R12] 页面在主要手机尺寸和电脑屏幕上可读可点，关键流程可用键盘完成，录音和照片权限拒绝时提供文字或文件选择替代方式，不依赖颜色单独表达成功或危险。
- [DZ-MUST:R13] 使用者能在应用内保存一条不默认附带健康原文或密钥的内测问题记录，包含当前页面、发生时间和用户描述，供后续修复和回归验证。

## 4. 关键状态和恢复

- **还没有记录**：说明三种录入方式，不显示虚构示例为本人数据。
- **正在保存或上传**：防止重复提交，断网后保留未提交输入，恢复后使用同一次幂等请求续传。
- **正在识别或整理**：页面可离开，返回后能重新读取持久化状态。
- **AI 失败**：原话或原件仍可查看，可手工补充、显式重试或稍后继续。重试要显示会再次调用外部 AI。
- **旧草稿存在但新整理失败**：旧草稿明确标为旧版，不冒充本次成功。
- **版本冲突**：先读取最新版本，保留本次输入，让使用者选择重新修订，不静默覆盖。
- **会话失效或断开**：清楚说明需重新进入，不把本地访问错误说成 AI 失败。
- **删除**：先展示将删除的记录、原件和关联影响，再二次确认；删除失败时不显示成已删除。
- **备份恢复**：先验证备份完整性并预览条数和媒体数量；恢复到隔离位置验证通过后，才能明确选择替换当前数据。

## 5. 数据、AI、权限和费用边界

- 记录、修订历史、审计状态、媒体原件和内测反馈默认保存在内测环境的受保护存储中。
- 用户选择在线整理时，该条必要文字证据会发给 DeepSeek；选择在线识别时，该份录音或照片会发给 AIHubMix 及它代理的上游模型服务。
- 当前未取得可绑定本版的服务商数据留存、人工查看或模型训练保证；页面保留这项未验证说明，不默认做否定性承诺。
- 使用者可关闭在线 AI，继续保存原件、手工录入识别文字和手工整理。
- 页面不读取、显示或导出 API 密钥；日志、反馈和备份也不包含密钥。
- 只有使用者主动发起识别、整理或显式重试才会产生付费 AI 请求。本版不在后台轮询时重复计费，不自动换付费模型。
- 删除只能证明内测环境本地副本被删除；不在没有服务商证据时承诺已删除对方曾处理的数据。

## 6. 以后再看

- 家属、照护者和医护的多角色协作。
- 公网注册、多人账号、组织隔离、支付和订阅。
- 加密云同步、自动跨设备恢复和家庭共享。
- 提醒计划、药物库、医院系统或穿戴设备对接。
- 复杂医学影像解读，包括 CT、MRI、X 光或病理图像的诊断性分析。
- 自动对外发送就诊材料。

## 7. 明确不做

- 不诊断疾病，不预测病情，不自动改药或生成个人化用药建议。
- 不把 AI 输出写成医生意见，不把本地规则未命中写成医学正常。
- 不代替急救服务或专业医疗判断。
- 不自动发送、发布、分享或购买任何外部服务。
- 不把比赛任务分工、演示话术或人造样例放在使用者主界面。

## 8. 第一版怎样算通过

1. 所有者能从目标手机浏览器进入，未授权浏览器被拒绝。
2. 一条文字记录能完成保存、真实 AI 整理、核对、查找和修订。
3. 一段目标浏览器录制的真实 WebM/实际媒体格式能完成原件保存、真实识别、安全扫描和记录关联。
4. 一张目标手机拍摄的真实照片能完成同样的保存、识别和关联流程。
5. 分别演练断网、AI 超时/失败、权限拒绝、重启和版本冲突，确认原始资料不丢、页面不虚假报成功且有恢复动作。
6. 用至少六条不同日期和类型的合成或打码记录，验证时间线查找、筛选、历史、选取交接和 PDF 导出。
7. 对一份不含密钥的备份执行完整性检查、隔离恢复和数据/原件对比，再演练一次有预览的替换恢复。
8. 在关闭在线 AI 后，仍能保存原件和手工完成记录；重新开启前页面会再次告知数据外发对象。
9. 删除一条专用测试记录时先看到影响预览；确认后记录和关联本地原件不再可读，其他记录不受影响。
10. 所有者从真实使用页面保存一条内测反馈，反馈不含健康原文、媒体或 API 密钥。

## 9. 当前带着的未确定性

- 首个手机私有访问方案还没有选定；需在技术方案中比较本机私有网络和受保护内测地址，不直接公网暴露现有服务。
- AIHubMix 和 DeepSeek 对这一具体 API 使用方式的留存、人工查看和训练政策尚未取得可验证结论；这会在内测页面明示，真实敏感内容是否外发由所有者决定。
- 现有录音只有合成 WAV 真实识别成功证据，浏览器 WebM 和目标手机必须重新验收。
- 现有备份脚本有技术测试，但用户界面、隔离恢复和从备份中排除密钥需作为本版正式功能验收。
