# 病历不归零·内测版产品规格（前后端分离版）

> 决策来源：2026-09-16 项目所有者确认“一个 GitHub 项目，前端和后端分别运行，使用者只打开前端页面”。
>
> 本版取代 `spec-local-first.md` 中“一个 veFaaS 地址同时提供页面和接口”的部署表述。本地加密主数据、人工核对、AI 外发同意、TOS 密文备份和安全边界不变。

## 1. 产品和使用者入口

“病历不归零·内测版”是一个面向真实使用的私密健康记录工具。使用者通过文字、录音或照片留下原始资料；AI 只生成待核对草稿；人工确认后形成可查找、可修订、可备份、可用于就诊沟通的连续记录。

对使用者只提供前端 Web 地址。打开该地址必须显示完整产品页面，不显示 JSON、健康检查结果、后端说明或服务器目录。后端 API 有独立地址，仅由前端调用，不作为产品入口分享。

## 2. 前后端关系

- GitHub 只保留一个项目，同时包含 `frontend/` 和 `backend/`。
- 本地开发时，前端默认使用 `http://127.0.0.1:5173`，后端默认使用 `http://127.0.0.1:18768`。
- 正式内测时，前端 Web 服务和后端 API 服务分别部署，拥有不同地址。
- 前端通过明确的 API 基础地址调用后端，不猜测、不静默改用其他服务。
- 后端只允许配置过的前端来源跨端口/跨域调用，并继续校验登录会话、CSRF、内容大小和操作权限。

## 3. 本地优先数据

- 健康记录、修订历史、媒体原件和内测反馈默认加密保存在当前设备浏览器中。
- 未解锁本机资料时，页面不能读取或修改健康正文。
- 前端与后端分离不改变数据边界；后端不增加健康明文数据库。
- 不同设备默认不自动同步；通过设备端加密备份进行迁移或恢复。

## 4. AI、云备份和费用

- 文字整理使用 DeepSeek，录音和照片识别使用 AIHubMix 及其上游模型。
- 只有使用者明确同意并主动发起时才把选中资料发给外部 AI；失败不自动重试。
- 私有 TOS 只保存浏览器已加密的备份；恢复口令和 API 密钥不上传。
- 前端包中不得包含 DeepSeek、AIHubMix 或火山引擎长期密钥。
- 只有使用者主动请求 AI 或备份时产生对应外部调用；部署资源按量计费，不默认启用常驻实例。

## 5. 内测范围

本版必须支持：所有者访问保护、本地加密仓库、文字/录音/照片记录、待核对 AI 草稿、时间线和筛选、修订历史、选中删除、就诊材料打印/PDF、本地加密备份、私有 TOS 密文备份、隔离预览恢复和内测问题记录。

本版不包含：多人账户、家庭协作、实时跨设备同步、医生签名、医疗诊断、药物调整指导、自动对外分享和复杂医学图像解读。

## 6. 必须可验收的结果

- [DZ-MUST:R1] 使用者能在手机和电脑的受支持浏览器中打开“病历不归零·内测版”；未通过所有者访问保护的人不能使用在线 AI 或备份能力，未解锁本地数据的人不能读取或修改当前设备上的健康资料。
- [DZ-MUST:R2] 使用者能通过文字、浏览器真实录音和真实照片创建记录，并在任何 AI 处理前看到原话或原件已经加密保存到当前设备的明确状态。
- [DZ-MUST:R3] 录音和照片在真实 AI 服务中成功识别后才显示识别文字；处理中、失败、超时、断网、权限拒绝和额度问题都有明确说明，失败不删除原件，付费 AI 请求不自动重试。
- [DZ-MUST:R4] AI 整理结果始终显示为待核对草稿，使用者能对照原始资料确认、退回或修订；确认只表示记录准确，不表示医生确认、诊断或风险消失。
- [DZ-MUST:R5] 使用者能在当前主设备的连续时间线中按关键词、日期范围、记录类型和处理状态查找记录，并查看原话、原件、AI 草稿、当前状态和修订历史；页面不把不同设备的独立本地数据误称为已经自动同步。
- [DZ-MUST:R6] 使用者能通过保留历史的方式修订记录，也能在看到本地数据和密文备份的具体影响并二次确认后删除选中的记录及其本地原件；删除不得连带其他记录、恢复密钥或 API 密钥。
- [DZ-MUST:R7] 使用者能选择日期范围和记录生成就诊材料，预览中保留原话、来源、未确定时间、待处理项和安全提醒，并能使用浏览器打印或导出 PDF，不自动对外分享。
- [DZ-MUST:R8] 使用者能在设备端创建包含记录和媒体原件、不包含 API 密钥的加密一致性备份，选择下载到自己的文件位置或上传密文到私有 TOS，并能在新设备的隔离区预览、恢复和验证，不静默覆盖现有数据。
- [DZ-MUST:R9] 页面在空数据、加载、保存中、上传中、AI 处理中、待核对、断网、重启、会话失效、本机空间不足、备份过期、备份失败、局部失败和恢复后都给出真实状态和可继续动作，不将“已接受”、“处理中”、旧草稿或旧备份显示成本次成功。
- [DZ-MUST:R10] 在首次使用真实 AI 前，页面明确说明选中的文字会发给 DeepSeek，选中的录音或照片会发给 AIHubMix 及其上游模型服务；使用者可以不同意外发而继续本地保存和手工整理，页面不宣称未经核实的服务商保留或训练政策。
- [DZ-MUST:R11] 本地危险提醒和专业复核线索在保存、AI 失败、核对、修订、时间线、就诊材料和备份恢复后都不被静默清除；未命中规则不显示成“正常”或“无风险”。
- [DZ-MUST:R12] 页面在主要手机尺寸和电脑屏幕上可读可点，关键流程可用键盘完成，录音和照片权限拒绝时提供文字或文件选择替代方式，不依赖颜色单独表达成功或危险。
- [DZ-MUST:R13] 使用者能在应用内保存一条不默认附带健康原文或密钥的内测问题记录，包含当前页面、发生时间和用户描述，供后续修复和回归验证。

## 7. 额外的前后端分离验收

1. 本地同时启动两个服务后，打开 `5173` 显示完整产品页面，`18768` 只提供 API。
2. 前端从 `5173` 能完成后端登录、会话状态、受保护 AI 请求和备份授权请求。
3. 未配置的第三方网页不能携带会话调用后端；合法前端跨域请求包含准确的允许来源和凭证头。
4. 正式内测只分享前端地址；README 不再把后端地址写成使用入口。
