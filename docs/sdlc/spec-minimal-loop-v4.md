# 病历不归零·内测版产品规格（最小闭环修订）

> 继承 `spec-split-web-api-v2.md` 中未被本文件修改的本地加密、原件保留、医疗安全和前后端分离约定；取代 `spec-device-binding-v3.md` 的设备绑定与逐次 AI 确认设计。决策来源：2026-09-18 项目所有者明确要求先删除这两层，跑通保存、读取、报告的最小 MVP。

## 1. 当前 MVP 的唯一主流程

1. 使用者输入文字、录音或拍摄资料照片。
2. 文字直接加密保存在当前设备；录音和照片先保存原件，然后自动发起识别。
3. 识别成功后，识别文字自动成为一条可核对记录，不再要求使用者额外点击“保存为记录”。
4. 已保存内容可随时读取、查找和核对。
5. 使用者可从已保存记录生成就诊交接材料，直接向医生展示、口述或打印。

## 2. 当前版本明确删除

- 不弹出“是否将内容发给 AI”的逐次确认对话框。
- 不要求家属或管理员先绑定设备，不显示“在线识别尚未由家属开通”或类似文案。
- 不在设置页显示设备绑定状态。
- 私有云备份不属于本轮最小闭环，页面暂不提供上传和查看云备份入口；本地加密备份继续保留。

## 3. 保留的必要保护

- 本机恢复口令继续用于加密当前设备上的健康资料；它不是网站第二道密码。
- API 密钥只在后端使用，不进入前端、本地健康记录或日志。
- 后端继续校验配置好的精确前端来源、请求大小和媒体类型。
- 原件在识别成功或失败时都不删除；失败时只告知“原件已保存，可重试”，不将失败伪装成成功。
- 报告是就诊沟通材料，不是诊断，不建议增减药物。

## 4. 本轮验收结果

- [DZ-MUST:R1] 使用者只需解锁本机加密资料；保存录音或照片后不弹 AI 发送确认，不检查家属设备绑定，而是直接开始识别。
- [DZ-MUST:R2] 文字、录音原件和照片原件可加密保存并重新读取；识别成功后自动生成可核对记录。
- [DZ-MUST:R3] 就诊交接材料能汇总选中记录及原件状态，且可供医生直接查看或打印。
- [DZ-MUST:R4] 页面与前端源码不包含家属绑定提示、设备激活调用或逐次 AI 确认调用；识别失败时保留原件和重试入口。

## 5. 发布边界

这个无登录、无设备绑定的版本只用于本地或受控内测。未加入限流、用量配额或新的简化访问保护之前，不将可消耗 AI 额度的后端直接作为公开互联网服务发布。
