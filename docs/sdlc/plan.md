# 病历不归零·内测版：技术实施与验收方案（草案）
## 1. 技术结论

本次采用“保留可靠底座，补齐正式产品能力”的路线，不重写现有系统，也不把当前本地服务直接暴露到公网。

- 保留 Python 标准库 HTTP 服务、SQLite、原始媒体存储、AI 适配器、版本历史、安全规则和现有测试。
- 前端继续使用原生 HTML、CSS、JavaScript，重构成可长期使用的产品界面；本版不引入 React、微服务或云数据库。
- 正式运行时只监听本机回环地址，由 Tailscale Serve 提供尾网内的私有 HTTPS 地址。明确不启用 Tailscale Funnel，不创建公开网址。
- 文字整理继续使用当前 DeepSeek 配置；录音和图片识别继续使用 AIHubMix 及已经验证的轻量模型配置。模型和费用上限由环境配置控制，付费调用不自动重试。
- 第一版只服务项目所有者本人。多人账号、公网注册、家庭协作和自动云同步继续留在后续版本。

这是“采纳但调整”的方案：正式内测值得开始，但现有 Demo 不能直接作为公网产品发布。私有网络方案的具体代价是电脑和手机都需安装并登录 Tailscale，电脑关机时手机不能访问；换来的好处是无需新增云服务器和公开攻击面。若以后需要长期公网在线，再单独评估受保护的云部署，不在本次顺带扩张。

相关外部依据：

- [Tailscale Serve 官方说明](https://tailscale.com/docs/reference/tailscale-cli/serve.md)：可把本机服务通过尾网内 HTTPS 提供给自己的设备，并可使用后台模式保持配置。
- [Tailscale 当前价格页](https://tailscale.com/pricing)：Personal 方案当前标为免费，适用于个人、非商业使用；实际条款和价格以后仍可能变化。

## 2. 目标运行形态

### 2.1 本机服务

- 新增正式启动入口 `scripts/start_app.py`，默认读取 `.env`，使用正式鉴权和数据目录。
- 服务只绑定 `127.0.0.1`；局域网和公网网卡不直接监听。
- 保留 `scripts/start_demo.py` 作为开发兼容入口，但主 README 和用户启动说明只介绍“内测版”。
- 启动前执行配置检查、数据库备份和幂等迁移；失败时停止启动，不带着半完成迁移继续运行。

### 2.2 手机私有访问

- 在电脑和目标手机安装 Tailscale，并加入同一个由项目所有者控制的 tailnet。
- 使用 Tailscale Serve 把本机端口映射为尾网内 HTTPS 地址；不启用 Funnel。
- 未加入该 tailnet 的设备无法到达服务；到达服务后仍需通过应用自己的所有者登录。
- Tailscale 是外部网络访问依赖，会按其政策处理账号和连接元数据；应用不主动把数据库、媒体原件或 API 密钥复制给 Tailscale。
- 提供停用说明：停止 Serve 后地址立即不可用，本机数据不受影响。

### 2.3 已知限制

- 电脑必须开机、联网且应用正在运行，手机才能访问。
- 本版没有异地云备份和自动同步；备份由使用者主动创建和妥善保存。
- Tailscale 安装、登录和设备加入仍需项目所有者完成账号交互，代码不能代替所有者授权外部账号。

## 3. 安全、身份和隐私

### 3.1 所有者登录

- 复用现有 `households`、`users`、`sessions` 和 PBKDF2 密码能力。
- 首次所有者创建只能从本机回环地址完成；完成后关闭初始化入口。
- 正式入口禁用匿名兼容会话。未登录请求不得读取前端数据接口、媒体或导出内容。
- 浏览器会话改用同源 `HttpOnly`、`SameSite=Strict` Cookie；正式 HTTPS 环境启用 `Secure`。
- 状态变更请求增加 CSRF 防护；登录继续使用限速和临时锁定。
- 登出、密码变更、备份替换恢复后使旧会话失效。

### 3.2 在线 AI 同意

- 新增本地应用设置，记录在线 AI 是否开启、告知版本和确认时间，不记录 API 密钥。
- 首次真实调用前明确展示：文字发给 DeepSeek；选中的录音或图片发给 AIHubMix 及其上游模型服务。
- 未同意或关闭在线 AI 时，保存原件和文字记录仍正常工作，并允许手工填写转写、图片摘要和整理内容。
- 每次显式重试前提示会再次调用外部服务；后台状态查询只读本地状态，不触发新的付费请求。
- 页面不承诺未经核实的服务商留存、训练或人工查看政策。

### 3.3 密钥和日志

- API 密钥仅从本机环境读取，不写入数据库、接口响应、页面、反馈、日志或备份。
- 错误日志只保留白名单错误类别、请求关联号和时间，不保存健康原文、识别全文或模型原始响应。
- 增加敏感信息回归扫描，覆盖备份、反馈、HTTP 错误和测试证据。

## 4. 数据与接口改造

### 4.1 数据迁移

在现有 SQLite 上做向前兼容的幂等迁移，新增或扩展以下数据：

- `app_settings`：在线 AI 同意、界面主题和告知版本。
- `feedback`：用户描述、页面、发生时间、处理状态；默认不关联健康记录或媒体。
- `erasure_jobs`：删除预览摘要、确认时间、结果和不含健康正文的审计信息。
- 必要的查询索引：记录时间、类型、处理状态和可搜索文本。

迁移前自动创建数据库和媒体清单备份。迁移失败时保留原数据库并停止正式启动。

### 4.2 时间线和查找

- 扩展事件列表接口，支持关键词、日期范围、记录类型、处理状态和分页。
- 详情接口统一返回原话、媒体、当前草稿、确认状态、危险提醒、专业复核线索和修订历史。
- 搜索结果只包含当前所有者的数据；没有结果时给出清除筛选和继续记录的动作。

### 4.3 修订和删除

- 普通修改继续创建新修订，不覆盖历史。
- 删除采用两步流程：先生成影响预览，再由使用者输入确认动作并提交。
- 影响预览列出将失去的记录、修订、媒体原件和包含该内容的就诊材料，不扩大到无关记录。
- 提交删除时，先把待删媒体移动到本机隔离区，再在单个数据库事务中删除健康正文、修订内容和关联副本，并保留只含标识、时间、数量和哈希的删除凭据。
- 数据库事务失败时把媒体移回原处；事务成功后再清理隔离媒体。清理失败会显示待处理状态并可安全继续，不谎报全部完成。
- 历史引用只显示“该记录已删除”的占位，不保留可还原的健康正文。
- 删除只证明本内测环境的本地副本已清除，不承诺第三方曾处理数据的远端删除。

### 4.4 就诊材料

- 交接接口支持日期范围和选中的记录 ID；保留现有全量生成方式作为内部兼容路径。
- 生成前展示选择范围，生成后预览原话来源、时间不确定项、待核对项、安全提醒和专业复核线索。
- 使用浏览器打印样式导出 PDF，不自动上传或发送给任何人。
- 如果源记录后来删除，旧交接材料同步去除相关健康正文并标记已删除。

### 4.5 备份与恢复

- 复用现有一致性备份和清单校验，新增可下载的 ZIP 包，包含数据库、媒体原件和 manifest，不包含 `.env`、密钥或运行日志。
- 设置页能创建、下载、列出和检查备份，显示创建时间、记录数、媒体数、校验结果和版本。
- 恢复分两步：先上传到隔离目录并校验、预览，再重新验证所有者身份并明确确认替换。
- 替换前自动创建当前数据备份；新数据在隔离位置通过结构和文件校验后再原子切换。
- 恢复失败时继续使用原数据；恢复成功后旋转会话，并重新检查记录数、媒体哈希和安全标记。

### 4.6 内测反馈

- 设置页提供本地问题反馈表单，只保存用户描述、当前页面和发生时间。
- 不自动附带健康原文、媒体、API 密钥、完整请求或模型响应。
- 反馈可在本地标记为待处理、已修复或不处理，为后续回归验证保留编号。

## 5. 正式产品界面

设计方向是“可信、克制、易核对的健康记录工具”，不是比赛展示页，也不是营销落地页。视觉变化强度保持中低，信息密度适中，动效只帮助理解保存、处理和恢复状态。

### 5.1 页面结构

1. 登录和首次设置：创建所有者、登录、查看本机与在线 AI 边界。
2. 今天：文字、录音、照片三个主入口，先保存原件，再显示处理进度。
3. 时间线：搜索、筛选、详情、修订、核对和删除。
4. 就诊材料：选择范围、预览、打印或导出 PDF。
5. 设置：AI 开关、连接状态、备份恢复、主题、私有访问说明和内测反馈。

### 5.2 界面规则

- 产品名统一为“病历不归零·内测版”，主界面不出现比赛、参赛、Demo 或任务分工文案。
- 保留现有品牌紫色但降低装饰性，不使用 AI 发光渐变、伪医学绿色或夸张卡片堆叠。
- 采用 CSS 变量实现浅色和深色主题，使用系统字体和文本优先的控件；主流程不依赖自绘图标。
- 手机优先但不锁死为固定画布；电脑端使用可读宽度和真实响应式布局。
- 交互目标至少满足常用触控尺寸，焦点清晰，键盘可完成主要流程，状态不只靠颜色表达。
- 权限拒绝时提供文字和文件选择替代方式；断网、处理中、失败、旧草稿和恢复成功都有明确、不同的文字状态。
- 尊重 `prefers-reduced-motion`，避免持续循环装饰动画。

## 6. 分阶段实施

### W1 正式运行与访问保护

覆盖 R1、R9、R12。

- 建立正式启动入口、强制鉴权、Cookie 会话、CSRF 和首次所有者设置。

通过条件：未登录浏览器和非 tailnet 设备均不能读取数据；目标手机可通过私有 HTTPS 登录；重启后数据和登录边界符合预期。

### W2 原件优先、在线 AI 同意与真实媒体

覆盖 R2、R3、R4、R10、R11、R12。

- 增加在线 AI 告知与开关、手工转写和手工整理路径。

- 验证目标浏览器录制格式、手机照片格式、超时、断网、权限拒绝和额度错误。

通过条件：关闭 AI 也能完成本地记录；开启后只有显式动作产生外部调用；一次真实 WebM 和一张真实手机照片在不丢原件的前提下闭环。

### W3 时间线、核对、历史和删除

覆盖 R4、R5、R6、R9、R11。

通过条件：至少六条打码或合成记录可按全部维度找到；专用测试记录删除后正文和原件不可读，其他记录、密钥和安全标记不受影响。

### W4 就诊材料和 PDF

覆盖 R7、R9、R11、R12。

- 实现日期和记录选择、内容预览、删除同步和打印样式。

通过条件：使用合成或打码数据生成一份可读 PDF；没有发生网络分享；未确定信息和安全提醒没有丢失。

### W5 备份、恢复、设置和反馈

覆盖 R8、R9、R10、R13。

- 实现备份 ZIP、清单预览、隔离恢复、替换确认、会话旋转和本地反馈。

通过条件：备份中找不到密钥；隔离恢复的数据和媒体哈希一致；替换失败能回到原数据；反馈不包含健康原文和密钥。

### W6 全量验收和真实试用交接

覆盖 R1 至 R13。

- 运行全部 Python、前端和 TypeScript 合同测试。
- 运行真实浏览器端到端流程、手机尺寸、键盘、深色主题、断网和重启测试。
- 使用合成或打码材料完成一轮低成本真实 AI 验收；任何新的付费调用、真实健康资料外发和第三方账号动作仍在执行前单独显示范围。
- 做密钥泄漏、备份内容、删除边界、鉴权绕过和依赖检查。
- 更新 README、内测使用说明、已知限制、恢复步骤和 GitHub 主干发布记录。

通过条件：13 项必做要求都有当前提交上的可复现证据；没有高严重度未解决问题；所有者能按说明从手机完成主要流程。

## 7. 测试策略

### 7.1 每个工作项

- 先为失败状态和边界写回归测试，再实现最小改动。
- 每次改动运行相关 Python 测试、前端 Node 测试和 TypeScript 合同检查。
- 涉及数据库的测试使用临时目录，不操作现有真实数据。

### 7.2 候选版本

- 全量回归必须保留现有 744 项通过基线，并增加本版的新测试；不能通过删除旧测试换取绿色结果。
- 浏览器验收覆盖桌面 Chrome 和目标手机浏览器；Safari 或目标浏览器不支持的能力必须有文字或文件替代方式。
- 故障注入覆盖网络中断、AI 超时、AI 认证失败、余额或额度问题、媒体写入失败、数据库事务失败、备份损坏和恢复中断。
- 所有“成功”都以重新读取持久化结果为准，不只看按钮提示或 HTTP 状态码。

### 7.3 真实外部调用边界

- 首轮开发和绝大多数回归使用离线提供者、合成资料或打码资料，不产生费用。
- 真实 AI 验收每种媒体只做约定次数，不自动重试、不自动换高价模型。
- 过去对合成资料的调用授权不自动延伸到真实个人健康资料；若要发送真实敏感内容，仍需在当时说明对象、范围和费用后由所有者决定。

## 8. 发布、回滚和运维

- 每个工作项形成独立、可审查的提交；完成当前候选版本后再合入 GitHub 主干。
- 数据库迁移、恢复和候选发布前都创建可验证备份；回滚代码不回滚或覆盖用户新产生的数据。
- 正式启动失败时保留原数据并输出非敏感诊断；不自动重置数据库。
- 私有访问出现问题时可停止 Tailscale Serve，回到本机 `127.0.0.1` 使用；不影响数据库和媒体。
- README 只承诺已经验证的功能，比赛资料移入历史说明，不从 Git 历史中破坏性删除。
- 内测期间按反馈编号修复；普通实现缺陷直接回归，涉及访问、外发、删除、费用或产品范围的变化重新形成可见方案。

## 9. 当前不在本方案内

- 公网域名、云服务器、7×24 小时托管和公开注册。
- 多人共享、家属角色、组织权限、支付订阅和商业合规承诺。
- 自动云同步、自动远端备份和第三方医院系统连接。
- 医疗诊断、用药建议、复杂影像诊断和自动对外发送。
- 重新选择大前端框架或把现有 Python 服务拆成微服务。

## 10. 开工后的默认执行方式

方案确认后按 W1 至 W6 连续推进。普通代码缺陷、测试修复和界面细节不逐步询问；只有以下情况暂停：

- 需要发送真实健康资料、产生未约定费用或操作第三方账号；
- 需要公开发布、删除现有真实数据、覆盖备份或更换关键服务商；
- 发现规格本身无法安全实现，或出现高严重度安全、隐私、数据丢失风险；
- 目标手机或外部服务必须由所有者完成登录、系统权限或设备侧操作。
