# 病历不归零·内测版实施方案（设备绑定修订）

> 依据：`spec-device-binding-v3.md`。未被本文件修改的 `plan-split-web-api-v2.md` 条款继续有效。

## 1. 前端

1. 删除在线密码弹窗及 `/api/app/login` 调用。
2. 启动时检查 URL 片段中的短时绑定令牌，调用设备激活接口后立即清除片段。
3. AI 和云备份静默复用 HttpOnly 设备会话；在线未开通或失效时返回“请家属在这台设备重新绑定”，不弹出阻塞对话框。
4. 本地 IndexedDB、加密、记录、修订、查找和本地备份完全不依赖设备会话。
5. 每次 AI 外发仍保留独立、明确的同意确认。

## 2. 后端

1. 使用 `APP_SESSION_SECRET` 签发并验证短时设备绑定令牌。
2. 新增设备激活接口，只接受精确允许来源；成功后写入带 `Max-Age`、HttpOnly、SameSite 策略的持久设备会话 Cookie。
3. 保留管理员密码接口用于管理和兼容，但老人前端不再调用。
4. 生产默认禁止自动绑定；本地开发自动绑定必须同时满足显式开关、回环客户端和配置过的回环前端来源。
5. 不把管理员密码、绑定令牌、API 密钥或健康明文写进前端包、本地存储或日志。

## 3. 验证与发布

1. 单元和 HTTP 回归覆盖令牌签名、篡改、过期、持久 Cookie、来源拒绝、CSRF 和自动绑定闭合条件。
2. 前端合同测试确认没有第二密码框、没有老人端管理员登录调用，并存在绑定失效的非阻塞提示。
3. 真实浏览器从前端端口验证：本机解锁、无第二密码、设备会话、刷新复用、本地记录不受在线状态影响。
4. 全量 Python、Node、TypeScript、密钥扫描和构建检查通过后，提交确切发布修订并更新 GitHub `main`。
