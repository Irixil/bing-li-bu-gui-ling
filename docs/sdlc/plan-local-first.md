# 病历不归零·内测版：本地优先技术实施与验收方案（修订草案）

## 1. 技术结论

本次采用“在线应用，本地数据，加密备份”的路线，替代之前需要电脑保持在线的 Tailscale 路线。

- 使用火山引擎 veFaaS 和 APIG 提供长期在线的网页、访问保护和按次 AI 转发。
- 健康记录、修订历史、处理状态、危险提醒、内测反馈和媒体原件的日常主副本加密保存在使用者选定的主设备浏览器中。
- 使用者启用云备份后，浏览器先加密备份包，再通过短时授权上传到私有 TOS Bucket；veFaaS、APIG 和 TOS 不得到恢复密钥。
- 文字整理继续使用当前 DeepSeek 配置；录音和图片识别继续使用 AIHubMix 及已验证的轻量模型配置。付费请求不自动重试。
- 前端继续使用原生 HTML、CSS、JavaScript；后端继续复用现有 Python AI 适配、安全规则和媒体识别代码，不做 React 或微服务重写。
- 第一版只服务项目所有者本人。实时跨设备同步、多人账户和家庭协作继续留到后续版本。

这项路线变更的专业结论是“采纳但调整”：本地保存能减少云端健康明文和持续数据库成本，但单独依赖浏览器会产生清理数据、设备损坏和换机丢失风险。因此本版必须把加密备份、恢复演练、空间提示和恢复密钥边界作为核心功能一起交付，不能把它们留成以后再补。

## 2. 云端资源与隔离

### 2.1 复用范围

当前火山引擎账号中已有：

- Application `deepwe-frontend`，状态为部署成功。
- Application `deepwe-backend`，状态为部署成功。
- Serverless APIG Gateway `DeepWe`。

本项目只复用同一个账号、地域和现有 APIG 网关，不修改、不重新部署、不删除两个 DeepWe 应用。新建独立 Application 和底层 Function，暂定名称 `bingli-beta`，最终创建前先用资源 ID 再次确认目标。

### 2.2 veFaaS 应用职责

- 提供同源前端静态资源和 PWA 应用壳。
- 校验所有者访问凭据，签发短期安全会话。
- 转发使用者主动发起的 DeepSeek 和 AIHubMix 请求。
- 为当前所有者签发仅允许指定对象、指定动作、短时间有效的 TOS 上传或下载授权。
- 返回不含密钥和健康原文的健康检查、能力状态和错误分类。
- 不把函数 `/tmp`、实例内存或本地文件系统当作长期数据源。

### 2.3 TOS 备份职责

- 新建独立、默认私有、与函数同地域的 Bucket，不复用 DeepWe 业务桶。
- 只保存浏览器已经完成加密的备份对象，以及最小必要的格式版本、创建时间、密文大小和校验值。
- 对象名使用随机标识，不包含姓名、病种、记录标题或媒体文件名。
- 浏览器不接触长期火山 AK/SK；函数使用最小权限身份签发短时预签名授权。
- 客户端加密是隐私主边界；TOS 服务端加密作为第二层防护，不替代客户端加密。
- 配置保留规则，避免无限累积旧备份；清理旧版本前必须保证至少一份已验证可恢复的备份仍存在。

官方依据：

- [函数临时目录说明](https://www.volcengine.com/docs/6662/149757)：`/tmp` 最大 512 MB，实例缩容时销毁，不能承担长期病历存储。
- [函数存储选型](https://www.volcengine.com/docs/6662/1356292)：TOS 和 NAS 是持久存储，临时硬盘只适合临时文件。
- [veFaaS 挂载 TOS](https://www.volcengine.com/docs/6662/1222882)：支持同地域私有 TOS，并建议使用最小权限身份。
- [TOS 浏览器上传](https://www.volcengine.com/docs/6349/127739?lang=zh)：浏览器上传应使用临时访问凭证，避免暴露账号长期密钥。

## 3. 本地数据设计

### 3.1 主数据

- 使用原生 IndexedDB 保存结构化记录、版本历史、状态、规则命中和媒体 Blob；不使用容量小且不适合二进制数据的 `localStorage`。
- 每台设备有独立的设备标识、数据结构版本和随机数据加密密钥。
- 使用 Web Crypto 在写入前加密健康正文和媒体；页面解锁后只在当前会话内持有解密能力。
- 本地索引只保留实现检索所必需的数据，并同样处于应用数据边界内。
- 使用 Storage API 展示当前占用、可用额度和持久存储申请结果；浏览器不支持或拒绝时如实提示。
- Service Worker 只缓存应用壳和非敏感静态资源，不把健康响应写入 Cache Storage。

### 3.2 解锁和恢复密钥

- 在线访问凭据负责保护 veFaaS、AI 和备份接口；本地解锁密钥负责解密设备数据，两者在权限上分离。
- 首次设置生成设备数据密钥，并用使用者设置的恢复口令派生密钥进行包裹；恢复口令不上传云端、不写入日志。
- 页面提供一次明确的恢复口令保存提醒和验证步骤；没有完成验证时不得把云备份显示为“可恢复”。
- 恢复口令丢失时，云端密文无法被项目方绕过解密。旧设备仍可解锁时，可以设置新口令并生成新备份。
- 口令派生参数带格式版本并在目标手机上做性能测试，避免过弱或导致页面长期卡死。

### 3.3 本地事务和结构升级

- 每次录入先在一个 IndexedDB 事务中保存原话、原件、幂等键和初始状态，再允许发起 AI。
- AI 返回结果写成新的草稿版本；失败只更新处理状态，不删除原件或覆盖旧草稿。
- 数据结构迁移先复制到新的对象仓库并校验，再切换活动版本；失败时继续使用旧版本。
- 当前本地 `runtime/records.sqlite3` 的记录、修订、媒体和交接材料均为 0 条，因此本版不开发没有实际数据可迁移的一次性导入功能。
- 切换前再次只读盘点旧数据库；如果仍为空则原样归档。如果出现真实记录，停止切换并先生成不含 `.env`、API 密钥、日志或历史测试凭据的显式迁移方案。

## 4. 访问保护和外部服务

### 4.1 所有者访问

- 正式入口不使用匿名 Demo 会话。
- 首次部署生成独立的所有者访问凭据，服务端只保存安全哈希或签名验证材料。
- 登录成功后使用同源 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie；状态变更接口使用 CSRF 防护。
- AI 和 TOS 授权接口必须验证会话、来源、内容大小、允许的操作和幂等键。
- 登出、访问凭据轮换或可疑会话处理后使旧会话失效。
- APIG 和函数层配置低流量内测所需的请求限制，防止公开 URL 被滥用消耗 AI 额度。

### 4.2 在线 AI 同意

- 新增本地设置，记录在线 AI 是否开启、告知版本和确认时间。
- 首次真实调用前明确展示：文字发给 DeepSeek；选中的录音或图片发给 AIHubMix 及其上游模型服务。
- 未同意或关闭在线 AI 时，保存原件、手工转写、手工摘要和手工整理仍正常工作。
- veFaaS 只在当前请求内转发所选资料，不把健康正文写入日志、TOS 备份元数据或函数持久存储。
- 每次显式重试前提示会再次调用外部服务；状态查看不会触发付费请求。
- 页面不承诺未经核实的服务商留存、训练或人工查看政策。

### 4.3 密钥和日志

- DeepSeek、AIHubMix 和 TOS 服务凭据只放在 veFaaS 生产环境的秘密配置中。
- API 密钥不进入前端包、接口响应、浏览器数据库、反馈、日志或备份。
- 错误日志只保留白名单错误类别、请求关联号、耗时和时间，不保留健康原文、识别全文、备份密文或模型原始响应。
- 增加构建产物、Git 历史差异、日志样例和备份包的敏感信息扫描。

## 5. 功能实现

### 5.1 录入与 AI

- 文字、录音和照片都先本地加密落盘，再允许调用在线服务。
- 浏览器录音保留实际 MIME 类型；服务端根据能力选择已验证适配器，不把 WebM 冒充 WAV。
- 图片和音频上传前检查大小与格式；发送给 AI 的处理副本不替代本地原件。
- AI 超时、认证失败、额度、网络和格式问题映射为可恢复状态；不自动重试、不自动切换高价模型。
- AI 输出始终是待核对草稿，确认不表示医生确认或诊断。

### 5.2 时间线与修订

- 本地查询支持关键词、日期范围、记录类型、处理状态和分页。
- 详情统一展示原话、媒体、当前草稿、确认状态、危险提醒、专业复核线索和修订历史。
- 修改创建新修订，不覆盖历史；版本冲突保留本次输入并让使用者选择。
- 页面明确当前数据来自哪台设备，以及最近成功备份时间，不显示不存在的实时同步状态。

### 5.3 删除

- 删除采用影响预览和二次确认，列出本地记录、修订、媒体、就诊材料和可能仍包含该记录的旧备份。
- 本地删除在一个事务中移除健康正文、修订副本和媒体，仅保留不含健康内容的删除凭据。
- 如果需要从备份中一并清除，先删除含该记录的旧密文备份，再上传不含该记录的新备份并验证；任一步失败都显示剩余副本状态。
- 不把“当前设备已删除”说成 DeepSeek、AIHubMix、其他设备或所有历史备份都已删除。

### 5.4 就诊材料

- 支持日期范围和记录选择，预览中保留原话来源、未确定时间、待核对项、安全提醒和复核线索。
- PDF 在浏览器本地生成或通过打印样式导出，不上传完整就诊材料到函数。
- 默认不分享、不发送；使用系统分享菜单仍由使用者明确发起。

### 5.5 加密备份与换机

- 浏览器把结构化数据、媒体原件、格式版本和完整性清单打包后，在本地完成认证加密。
- 支持下载加密备份文件，也支持通过短时预签名地址直接上传密文到私有 TOS。
- 上传完成后重新读取对象元数据或校验值，只有服务端对象存在且校验一致才标记成功。
- 页面显示本机最后变更、最后成功备份、待备份大小和失败原因；不在后台无限重试。
- 恢复时先下载密文到新设备隔离区，验证恢复口令、格式、校验值、记录数和媒体数，再明确选择合并或替换。
- 替换前自动导出当前设备备份；恢复失败时不修改当前活动数据。
- 第一版不做实时同步。换机流程是“旧设备完成并验证备份，新设备恢复并核对，最后再决定是否清理旧设备”。

### 5.6 内测反馈

- 页面提供本地问题反馈，只保存用户描述、当前页面和发生时间。
- 不自动附带健康原文、媒体、API 密钥、完整请求或模型响应。
- 第一版反馈留在本地并进入加密备份；以后若增加发送给开发者的能力，需要另行告知和确认发送内容。

## 6. 正式产品界面

设计方向是“可信、克制、易核对的健康记录工具”，不是比赛展示页，也不是营销落地页。视觉变化强度中低，信息密度适中，动效只解释保存、处理、备份和恢复状态。

### 6.1 页面结构

1. 访问与解锁：所有者登录、本地数据解锁、首次设备设置和恢复入口。
2. 今天：文字、录音、照片三个入口，先保存原件，再显示 AI 进度。
3. 时间线：搜索、筛选、详情、修订、核对和删除。
4. 就诊材料：选择范围、预览、打印或导出 PDF。
5. 设置：本机空间、最近备份、恢复演练、AI 开关、连接状态、主题和内测反馈。

### 6.2 界面规则

- 产品名统一为“病历不归零·内测版”，主界面不出现比赛、参赛、Demo 或任务分工。
- 保留品牌紫色但降低装饰性，不使用 AI 发光渐变、伪医学绿色或夸张卡片堆叠。
- 使用 CSS 变量提供浅色和深色主题，以系统字体和文本控件为主；主流程不依赖自绘图标。
- 手机优先但不锁死为固定画布；电脑端使用真实响应式布局。
- 触控目标、键盘焦点、对比度和状态文字满足主要无障碍要求，状态不只靠颜色表达。
- 权限拒绝提供文字和文件选择替代；断网、处理中、未备份、备份失败、旧草稿和恢复成功有明确不同的状态。
- 尊重 `prefers-reduced-motion`，不使用持续循环装饰动画。

## 7. 分阶段实施

### W1 云端骨架与访问保护

覆盖 R1、R9、R12。

- 建立独立 veFaaS Application 和 Function，复用现有 APIG Gateway，不触碰 DeepWe 应用。
- 提供正式入口、强制鉴权、安全 Cookie、CSRF、限流和脱敏健康检查。
- 建立本地、预发布和生产配置边界，更新环境示例但不提交密钥。

通过条件：电脑关机后目标手机仍可打开页面；未授权浏览器不能使用 AI 或备份接口；现有 DeepWe 地址和版本不变化。

### W2 本地加密数据与结构升级

覆盖 R2、R5、R6、R8、R9、R11。

- 建立 IndexedDB 数据层、Web Crypto 密钥封装、空间提示、事务和迁移机制。
- 把现有录入、历史、安全标记和媒体关系迁移到浏览器主数据。
- 保留旧 SQLite 文件不动，上线前复核仍为空后归档；不为零数据开发一次性导入界面。

通过条件：关闭页面和重启设备后数据仍可解锁；未解锁页面无法读取正文；结构升级失败不破坏旧版本；旧 SQLite 文件未被覆盖或删除。

### W3 原件优先、AI 同意与真实媒体

覆盖 R2、R3、R4、R10、R11、R12。

- 实现在线 AI 告知、开关、手工转写和手工整理。
- 重整文字、录音、照片链路，确保本地保存早于 AI。
- 验证目标浏览器 WebM、手机照片、超时、断网、权限拒绝和额度错误。

通过条件：关闭 AI 仍能完整记录；开启后只有显式动作产生外部调用；真实浏览器媒体不丢原件并完成一次受控闭环。

### W4 时间线、历史、删除和就诊材料

覆盖 R4、R5、R6、R7、R9、R11、R12。

- 实现本地搜索筛选、详情、版本冲突、历史和删除影响预览。
- 实现选取就诊材料、本地 PDF 和删除后的引用处理。

通过条件：至少六条合成或打码记录可按全部维度查找；专用测试记录删除后本地正文和原件不可读；一份 PDF 不经过云端生成。

### W5 TOS 密文备份、恢复和反馈

覆盖 R6、R8、R9、R13。

- 创建独立私有 Bucket 和最小权限配置，接入短时预签名上传、下载和清理。
- 实现客户端加密包、下载备份、TOS 备份、校验、隔离恢复、替换保护和恢复口令流程。
- 实现本地反馈和备份状态中心。

通过条件：TOS 对象无法直接读取健康明文且不含 API 密钥或恢复密钥；全新浏览器资料目录可以恢复并核对记录和媒体；损坏备份不会覆盖当前数据。

### W6 全量验收、文档和主干发布

覆盖 R1 至 R13。

- 运行全部 Python、前端和 TypeScript 合同测试，并新增本版安全与恢复测试。
- 运行桌面和目标手机真实浏览器流程、键盘、深色主题、断网、空间不足模拟和重启测试。
- 使用合成或打码材料完成低成本真实 AI 验收；新的付费调用或真实健康资料外发仍在执行前说明范围。
- 检查鉴权绕过、TOS 授权越权、密钥泄漏、备份明文、恢复覆盖和现有 DeepWe 回归。
- 更新 README、内测说明、数据恢复说明、已知限制和 GitHub 主干发布记录。

通过条件：13 项必做要求都有当前提交和实际部署上的可复现证据；没有高严重度未解决问题；所有者能从手机完成录入、核对、备份和全新环境恢复。

## 8. 测试策略

### 8.1 本地与合同测试

- 每个失败状态和授权边界先建立回归测试，再实现最小改动。
- 保留现有测试作为 AI 适配、安全规则和迁移来源的回归基线；不能通过删除旧测试换取绿色结果。
- IndexedDB、Web Crypto、Service Worker 和 Storage API 用真实浏览器测试，不只依赖 DOM 模拟。
- 数据测试使用临时浏览器资料目录和临时数据库，不读取或修改真实健康数据。

### 8.2 故障与安全测试

- 覆盖网络中断、AI 超时、认证失败、额度问题、媒体写入失败、浏览器空间不足、备份上传中断、密文损坏、恢复口令错误和替换恢复中断。
- 验证预签名授权过期、对象路径越权、重复上传、旧会话、CSRF、公开 URL 滥用和日志脱敏。
- 所有“成功”以重新打开应用并读取持久化结果为准，不只看按钮提示或 HTTP 状态码。

### 8.3 真实外部调用边界

- 大多数回归使用离线提供者、合成资料或打码资料，不产生 AI 费用。
- 真实 AI 验收每种媒体只做约定次数，不自动重试、不自动换高价模型。
- 过去对合成资料的授权不延伸到真实个人健康资料。
- 创建 veFaaS Application、TOS Bucket、权限策略或其他可能计费资源前，展示资源名称、地域、用途和预计费用边界并取得一次明确授权。

## 9. 发布、回滚和成本

- 每个工作项形成独立可审查提交；当前候选版本通过后再合入 GitHub 主干。
- 新应用使用独立资源 ID 和路由；回滚只回滚本项目 revision，不回滚或覆盖 DeepWe。
- 浏览器结构升级、备份恢复和正式发布前创建可验证本地加密备份。
- 云端发布失败不删除本地数据；本地升级失败继续使用旧数据结构。
- TOS、veFaaS、APIG 和公网流量按实际使用可能产生费用；不宣称固定免费。部署后记录账单入口、费用开关和停止方法。
- AI 调用和备份上传都设置明确大小、次数和并发限制，避免失控费用。
- README 只承诺已经验证的功能；比赛材料移入历史说明，不从 Git 历史中破坏性删除。

## 10. 当前不在本方案内

- 实时双向同步、多人协同编辑和多设备自动冲突合并。
- 公网注册、家庭角色、组织权限、支付订阅和商业合规承诺。
- 把健康资料明文长期保存到 veFaaS 临时目录、普通服务器日志或公开对象存储。
- 医疗诊断、用药建议、复杂影像诊断和自动对外发送。
- 重写为大型前端框架、微服务或重新开发当前已验证的 AI 适配器。

## 11. 开工后的默认执行方式

本修订规格和方案确认后按 W1 至 W6 连续推进。普通代码缺陷、测试修复和界面细节不逐步询问；只有以下情况暂停：

- 需要发送真实健康资料、产生未约定 AI 费用或操作新的第三方账号；
- 需要创建可能计费的 veFaaS、APIG、TOS 或 IAM 资源；
- 需要删除或覆盖现有 DeepWe 资源、真实数据或已验证备份；
- 发现恢复密钥、备份、鉴权或数据迁移存在高严重度数据丢失或隐私风险；
- 目标手机或外部服务必须由所有者完成登录、系统权限或设备侧操作。
