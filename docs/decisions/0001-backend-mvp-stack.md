# 后端技术决策 0001：比赛 MVP 技术栈冻结

- 状态：B 工作基线；合入 `main` 前由项目负责人和集成人确认
- 日期：2026-09-12
- 适用范围：比赛 MVP 的后端数据与 HTTP 接口
- 负责人：B（后端数据/API）

## 背景

仓库没有单独记录过技术选型决策，但已有实现和验证事实：Python 3.12、标准库 HTTP 服务、SQLite、JSON Schema、pytest、GitHub Actions 已经承载原话保存、整理、核对、修订、历史、交接材料和离线失败兜底。当前本机复核结果为 71 项测试通过、40 条 Mock 回归通过、1 位公开病例的 3 段资料完成 HTTP 演示。

比赛 MVP 的首要约束是让老人端网页在本地稳定完成核心闭环。此时更换 Web 框架、ORM 或数据库会扩大改动面，却不会直接提高演示价值。

## 决定

比赛版本冻结以下技术栈：

| 层次 | 选择 | 约束 |
|---|---|---|
| 运行时 | Python 3.12 | 本地和 CI 使用相同主版本 |
| HTTP | Python 标准库 `ThreadingHTTPServer` | 只监听 `127.0.0.1`；JSON UTF-8；不作为公网服务 |
| 持久化 | SQLite + WAL + 显式 SQL 事务 | 原始证据、修订、审计和交接快照必须持久化 |
| AI 接入 | `Provider.complete_json` 接口及 Mock/真实模型适配器 | 模型是外部依赖；不得直接写数据库 |
| AI 输出合同 | JSON Schema Draft 2020-12，`event-v0.3` | 不符合结构、来源、时间和安全规则的输出不得写入草稿 |
| 接口合同 | `docs/API.md` + `contracts/api.ts` | 两处必须与 HTTP 行为同步；B 是收口人 |
| 测试 | pytest，以接口级集成测试为主 | HTTP 接口和 `SQLiteStore` 接口是 B 的主要测试接缝 |
| 持续集成 | GitHub Actions | 每次 push/PR 跑测试、Mock 回归和公开病例演示 |

TypeScript 只用于描述前端消费的 HTTP 合同，不代表 B 选择了前端框架。

## 本阶段明确不做

- 不迁移 FastAPI、Flask、Django 或其他 Web 框架。
- 不引入 ORM，不迁移 PostgreSQL、云数据库或对象存储。
- 不扩展子女端、医生端、支付、订阅或附件上传。
- 不把已有账号兼容层包装成公网多家庭鉴权能力。
- 不因代码排版问题大范围重写已验证模块。
- 不为了“架构完整”增加当前只有一种实现的抽象层。

## 模块接口与接缝

### 1. HTTP 模块

前端只需要学习固定端点、请求/响应、状态码、请求头和状态迁移，不需要知道 SQLite 表或模型供应商。`docs/API.md` 和 `contracts/api.ts` 共同构成它的接口。

B 通过真实本地 HTTP 验证这个接缝。测试不得直接查询数据库来证明前端可见行为。

### 2. 记录状态模块

`SQLiteStore` 隐藏事务、并发、不可变证据、版本检查、审计和快照细节。B 通过它的公开方法验证状态机；不依赖具体表结构断言业务行为。

必须保持的状态路径是：

`inbox → draft → recorded`，退回进入 `needs_review`，修订时旧记录进入 `superseded`、新记录从 `inbox` 开始。

### 3. 模型整理模块

`Provider.complete_json` 是真实外部依赖的接缝，Mock 是测试适配器，DeepSeek/ModelScope 是运行适配器。C 负责模型、提示词和危险规则；B 负责模型结果进入 HTTP 和数据库前后的保存、版本、错误和审计语义。

只有外部模型依赖可以 Mock。HTTP 模块和 `SQLiteStore` 之间不增加 Mock 层。

## 后端开发规则

1. 每次只完成一个可见行为：先写失败测试，再做最小实现，再运行相关测试和全量回归。
2. 测试描述用户或调用方能观察到的结果，不断言私有函数、SQL 调用次数或内部调用顺序。
3. HTTP 行为变化必须同时更新 `docs/API.md`、`contracts/api.ts` 和接口级测试。
4. 已发布的字段、状态码和错误码在接口冻结后不得静默更名；确需变更先通知 A、C、D、E。
5. 创建记录必须使用幂等键；整理、核对、修订必须使用正整数 `expected_version`。
6. 模型调用发生在数据库事务之外；创建接口成功后原文必须已经提交。
7. 原文、来源、发生时间和修订关系不可原地覆盖；修订只能创建新记录。
8. `422` 是“原文已保存、AI 整理失败”，不是整个创建流程失败；响应必须保留事件和本地安全结果。
9. `danger_detected=false` 只能解释为本地规则未命中，不能解释成医学正常。
10. 新增运行依赖前必须说明它解决的当前问题、替代方案和对离线演示的影响。
11. 新增 Python 模块使用清晰的四空格格式。对于尚未单独格式化的旧压缩模块，功能 PR 保持局部风格和最小差异；全文件格式化必须放在独立、无行为变化的 PR。
12. 密钥、`.env`、运行数据库、缓存和依赖目录不得进入 Git。

## 重新评估技术栈的触发条件

出现以下任一情况时另开决策，不在当前 PR 中顺带迁移：

- 产品需要公网部署或同时服务多个家庭。
- 需要正式身份认证、授权隔离、限流、监控和安全审计。
- 数据迁移、查询复杂度或并发量超出 SQLite 的本地单人范围。
- 接口数量增长到需要自动 OpenAPI、代码生成或成熟中间件。
- 真实用户试用证明当前运行方式阻塞核心任务。

在触发条件出现前，换框架不属于 B 的比赛 MVP 工作。
