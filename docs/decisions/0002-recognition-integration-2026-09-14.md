# 识别实现选择记录：保留 feaf182，不合入旧 recognition.py

日期：2026-09-14
范围：后端整合分支
结论：采用 feaf182 当前实现；不直接合入 feat/media-recognition@787e290。

## 保留当前实现的原因

- 当前媒体编排只读取已经保存的不可变原件，识别失败会留下原件、尝试状态和可重试入口。
- DashScope 流式入口限制为受信任的 WSS 地址，拒绝重定向；供应商响应有大小上限，错误不回显供应商正文、密钥或本地路径。
- OpenAI-compatible ASR/OCR 已用仓库合成 WAV/PNG 完成一次真实 HTTP 全链路，结果标记为非 Mock。该证据不外推到生产或临床。
- 当前测试覆盖 WebM 转 PCM、超时、响应冲突、临时文件清理、错误分类和原件保留。

## 不合入 Paraformer-v2 异步方案的原因

旧方案要求 DASHSCOPE_ASR_FILE_URL 指向公网可访问音频。识别函数接收本地原件路径，但异步 Paraformer 路径实际提交环境变量中的 URL，不能证明远端对象就是当前已保存原件。它还需要新增对象存储、预签名 URL、过期和删除策略、数据外传说明，以及远端结果 URL 的安全边界。

旧分支的提交/轮询/下载流程只有测试替身，没有真实 Paraformer-v2 成功证据。整支合入还会覆盖当前 recognition.py、错误合同和现有安全测试，回归面大于本轮收益。

## 可保留的后续方向

- 长音频确实需要文件转写时，单独评估私有 OSS 和短期预签名 URL。
- 在调用前绑定本地 SHA-256、上传对象 SHA-256 与 attempt_id；回收对象并记录过期结果。
- 对任务查询和结果下载做 HTTPS 主机白名单、重定向拒绝、响应上限和超时控制。
- 使用合成或明确授权音频完成真实端到端测试；不能用替身测试冒充真实识别。
- 旧分支的本地 Whisper 与 macOS Vision 证据可作为离线候选研究，不作为本 MVP 依赖。
