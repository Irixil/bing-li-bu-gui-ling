## 产品方向与范围

给老人自己用的健康记录本：主要用语音和拍照留下今天发生的事情与已有资料，打字补充，下次就医带着连续记录说明情况。老人不必长期吃药才有使用价值。

比赛先证明“资料存得住、来源找得到、识别可核对、危险描述有提醒、下次沟通能带走”。本次不新增子女端、医生账号、支付、多租户或生产级公网部署；前端由项目负责人在独立任务负责，后端队友不展开前端页面设计。

媒体范围为一段录音／一张清楚的印刷资料照片，原件保存 → 中文文字识别 → 保留机器初稿与人工修改 → 关联 Event → 现有整理、核对、修订、历史和就诊材料。手写、复杂版式、长音频流式处理、说话人识别和复杂自动纠错不作为本次默认新增。

录音行为已确认：长时间没声音后先提醒，提醒后仍无回应再自动暂停，保留内容并可接着说。静音时长、提醒后等待时长、检测方法待真机验证小声、停顿、电视噪声后确定。**60 秒强制结束要求已撤回**；不得恢复为默认录音时长、后端拒收阈值或验收条件。暂停不等于上传成功或人工核对完成。

## 已有底座与不能冒称的能力

当前文本闭环已实现：输入原话 → SQLite 保存与有限本地危险扫描 → Mock 或文本模型整理 → 人工核对 → 历史／修订 → 交接快照。具备创建幂等、版本冲突和整理 422 保留原文。

当前没有录音／照片上传、媒体保存读取、ASR/OCR 或处理状态。`source_kind=audio_transcript/document` 只是来源标签。现有适配器只调用文本 `chat/completions`，现有备份只备份数据库。

原基线证据包括 71 项后端测试、40 条合成回归、1 位公开病例的 3 段摘要与进程重启。C 已补充通用文本模型适配、完整原文/来源绑定、模型失败审计、历史提醒保留、待专业复核候选及对抗测试；真实文本模型已有成功与失败批次证据。媒体、真实识别、真实老人使用和临床安全未验收。以 [VALIDATION.md](VALIDATION.md) 为证据入口，不能把自动测试或 Mock 结果当作真实模型质量。

## 最短实施顺序

1. 每人 Git 克隆、在 Codex 说明本人任务；只读核对当前文件、Git、DZ 记录和证据，讲清路线，得到本人确认后开发。
2. A 先收口 HTTP 与识别函数合同，B 和前端核对；B 同时调查实际可用服务。需要费用或资料外传时完成具体说明，由负责人确认。
3. A 做可恢复的保存底座；B 用独立文件做识别模块和真实小样。两人通过测试替身并行，不同时改数据库或大文件。
4. 分支 PR 提交，带运行说明、证据、未完成事项和依赖。集成人按合同与依赖合并，不整包覆盖，不同时直接推 main。
5. 在同一提交上联合验证成功、失败、丢响应、重启、人工改错、危险提醒、422、交接材料和备份恢复；手机 HTTPS、权限、编码、暂停续录与前端联调。
6. 根据真实通过结果冻结演示范围；尚未通过项保持可见。现场使用 Mock 时明确说明模拟，不把备用方案称为真实识别。

## 当前必须守住的边界

- “已保存”“文字识别完成”“记录已核对”是不同事实；原件未持久化不能显示已保存，识别成功不能自动核对。
- 识别有文字后立即扫描本地危险描述，先于整理；没有文字时不能宣称已扫描或“无危险”。已经命中的提醒不因核对而消失。
- 药名、数值、单位、日期不猜写；没有可靠来源的置信分数不能生成。原件、机器初稿、人工修改分别保留。
- 格式、大小、像素与后端支持时长等待服务和设备证据及确认。实际上传启用前必须有有限且可解释的限制，不能无限接收或暗中截断。
- 本机默认 `127.0.0.1:18768`，使用 `/health` 的 session_token 和 `X-Session-Token`；账号兼容路径后置。当前服务不能直接充当公网安全隔离服务。
- 本地危险规则覆盖有限，可能误报和漏报；C 已为带明确心率指标和分钟单位的低心率描述添加独立待复核候选，尚未获得医学阈值认证；其余数值和语义覆盖问题登记在 24 类医学待审清单。未命中不是正常结论，不诊断、不改药。
- C 已校验引用 ID 与完整原文、来源标签的对应关系，但来源标签不代表身份核验；历史账号隔离等限制仍在。文件存在不等于备份恢复可靠，必须有实际恢复证据。
- `.env`、数据库、私人录音／照片、依赖与模型缓存不进 Git。测试资料的使用授权和公开授权分别确认；公开病例保留来源与许可。

旧总包与前端未验收 worktree 保留，不由本后端任务覆盖。所有活跃需求以本仓库最新记录和项目负责人明确的后续纠正为准。
