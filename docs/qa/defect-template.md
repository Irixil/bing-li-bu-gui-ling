# 缺陷记录模板

复制本页后，把每个字段替换成事实；没有证据的字段写“未采集”，不要用推测补齐。

## 基本信息

| 字段 | 内容 |
|---|---|
| `defect_id` | `D-YYYYMMDD-###` |
| 发现阶段 | `T0` / `T1` / `T2` / `T3` / `T4` / `T5` / `T6` |
| 发现时间 | ISO 8601，含时区 |
| 基线提交 | `git rev-parse HEAD` 的完整值 |
| 环境 | 操作系统、Python、依赖安装方式、服务地址范围 |
| 责任人 | 负责修复或协调的人 |
| 状态 | `open` / `blocked` / `fixed` / `retest` / `closed` |
| 阻断级别 | `none` / `演示阻断` / `验收阻断` |

## 证据与修复

| 字段 | 内容 |
|---|---|
| 关联测试 | 例如 `TEXT-422-01` |
| 证据路径 | 相对仓库路径；附 SHA-256 |
| 关联 PR/提交 | 未提交时写“未修复” |
| 修复说明 | 只描述实际变更 |
| 复测命令 | 可复制的命令 |
| 复测结果 | `通过` / `失败` / `未执行` |
| 未完成事项 | 保留限制，不以关闭缺陷代替范围结论 |

## 关闭条件

只有复测证据覆盖原始复现步骤、预期结果和影响判断，且负责人确认演示/验收影响后，才把状态改为 `closed`。环境缺依赖、待定合同或尚未实现功能应保持 `blocked` 或 `retest`，不要伪装成已修复。
