# 任务 D 质量资料

这里保存公开病例、测试矩阵、缺陷记录和可复核证据的工作模板。它们只记录当前仓库能证明的范围，不把媒体草案、前端页面、真实 ASR/OCR 或真实用户效果写成已完成。

## 可重复校验

在仓库根目录运行 `python3.12 scripts/validate_task_d.py`，可离线检查登记表、逐案证据、SHA-256、矩阵编号和媒体/前端未完成边界。脚本只读本地 QA 资料，不启动服务、不联网、不读取密钥。

## 状态含义

| 状态 | 使用条件 |
|---|---|
| 已交付 | 当前提交上有可复现证据，且证据覆盖该行的全部验收条件。 |
| 条件式交付 | 测试步骤和预期已准备，但依赖待实现功能、待冻结合同或受控设备。 |
| 等待用户决定 | 需要负责人确认角色、公开范围、服务、费用、数据外传或演示口径。 |
| 明确不在范围内 | 本轮不负责或不能由任务 D 单独证明，例如临床安全和付费意愿。 |

“通过”只适用于具体用例，不自动代表整个产品、媒体能力或比赛页面通过。

`docs/evidence/source-manifest.json` 仍是既有代码/数据基线的历史清单，本轮新增登记和 QA 证据不直接改写它；本轮产物的校验和记录在各自证据文件中，待集成人确认后再统一更新清单。

## 角色边界

当前角色已由用户确认：承担任务 D（公开病例、测试和质量验收），不承担“老人端前端”实现。D 可以在前端提交后执行 UI/手机验收，但不修改 `frontend/`，也不把前端验收写成已完成。
