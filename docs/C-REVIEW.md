## 交付行为

当前模式为**结构整理、完整原文保留**。模型输出分类、复核要求、冲突候选，`summary` 保留当前整条原文，`claims` 按记录 ID 保留对应整条原文和来源，仅去除外围空白。原来的 500 字截断已删除；自由改写、部分摘录和无引用事实被拒绝。这样会拒绝某些合理摘要，这是本版有意选择的保守边界，不宣称已具备自由摘要能力。

- 来源、引用及冲突 ID 绑定，模型不能把家属转述升级成医生证据，也不能借另一记录的原话。
- 无后端发生时间就保留 null；不从其他记录或原文中出现的任意日期推断当前事件日期。
- 医疗追问只允许固定中性模板。修改事件类别不能绕过已识别的用药/医嘱专业复核；模型自报禁行动也拒绝。
- 活动版本统一为 `prompts/VERSION` 的 `prompt-v0.5`。实际提示词、Schema 和输入有哈希，成功/失败都有模型配置标识，存储重开后可查询。
- 模型输入仅含原始证据，旧草稿、核对备注和审计不作为模型事实发送。
- 规则升级 `offline-danger-v2`，补胸口很疼、突然右手无力、血压格式和受限呼吸表达，缩小明确否定及呕吐跨语句误报。另增加不改变急救等级的 `offline-review-flags-v1` 低心率临床复核候选旗标。
- 旧记录按新规则扫描；旧阳性提醒不静默清除，原数据库扫描和旧历史快照不回写。`historical_notice_preserved=true` 时前端显示历史提醒，不能仅看草稿 none。
- 评测分开统计结构、安全、自动语义断言、未判定项和数据标签问题；普通案例再多也不能抵消危险案例失败。错误报告不回显原始异常体或含凭据的 URL。

## 从第一性原理推导的审查准则

1. 系统没有独立观察到患者情况，原始输入只能被保存和归属，不能凭模型流畅程度增加事实。
2. 字符包含、Schema 合法、来源 ID 存在，各自都不足以证明语义忠实；数字、否定、条件、说话人和撤回语句属于同一证据上下文。
3. 系统没有诊断或处方授权，模型分类和用户确认都不能变成治疗许可或消除已有提醒。
4. 模型及网络可失败；保存和本地提醒必须先成立，失败不产生成功草稿，也不丢失审计。
5. 验证必须能证伪。没有执行的断言不能算通过，旧标签冲突不能靠改输出迎合，Mock 不能代替真实模型证据。

开发后由不同实现者交叉构造反例，根任务复现并补修。审查不限于已有测试通过率，先构造看似合法但违反以上准则的输出，再验证能否通过实际校验或 HTTP 链路。

## 对抗发现与处置

| 攻击或反例 | 发现 | 当前结果 |
|---|---|---|
| 原文超过 500 字，否定语境在尾部 | Mock 截断与引用校验冲突 | 完整保留，长文本回归通过 |
| “每次10毫克”截成“0毫克”，“180”截成“80” | 连续子串仍能改变剂量/数值 | 禁止片段截取 |
| “可以加倍是错误建议”截成“可以加倍” | 摘录移除了反对语境 | 摘要与证据必须整条原文 |
| 条件句、女儿说自己胸痛、多句撤回 | 关键词上下文解析仍可错置事实 | 删除不完备的摘录放行逻辑 |
| 输入散步，输出阿司匹林100毫克 | JSON 合法但事实无依据 | 拒绝自由生成摘要/claim/追问 |
| 把来源改为 clinician_evidence，交叉借 quote，伪造冲突 ID | 原校验只分别核对集合 | 按 ID 绑定来源和完整原文，冲突引用校验 |
| 把医嘱/给药记录分类成 other | 能绕过专业复核 | 原文复核路由及升级/角色一致性检查 |
| 旧草稿或核对备注放入模型 history | 模型旧结果可能成为新证据 | 原始证据字段白名单 |
| “没有胸痛但呼吸困难”、反问、双重否定 | 全句否定容易隐藏其他症状 | 只排除窄范围明确否定，其他命中保留 |
| “呕吐终于停了但止不住血” | 错误联接为持续呕吐 | 仅保留出血命中 |
| 旧 v1 记录未命中，新 v2 能识别，随后模型超时 | 422 和交接仍沿用旧阴性 | 旧记录重扫，成功/失败/重开/交接回归 |
| 非危险 34 例成功、危险 6 例失败 | 旧计数门槛可能假通过 | 任一适用安全断言失败都失败 |
| 模拟 Provider 的非法 JSON/数组、401、超时 | 不能仅证明 Mock 正常路径 | 两个真实 Provider 的协议模拟及 HTTP 失败保真回归 |

## 未完成和剩余风险

- 真实模型的可用性、延迟和对严格完整原文合同的遵从率仍未验证。可本地配置后运行下方 11 例命令。
- 分类、冲突判断及未覆盖症状仍会出错。冲突 ID 合法不等于语义上确有冲突；Mock 同类测量会产生粗糙冲突候选。
- 危险/专业复核路由仍是有限词表；心率候选目前只批量标记为待专业复核，不自动诊断或升级急救。口语、复杂否定、历史和纠正仍可能误报漏报。未命中不表示正常。
- `source_kind` 是输入标签，不验证医生身份或文档真实性；客户端发生时间也未证明真实发生。
- 配置模型 ID 与输入/提示词哈希只能标识请求，不冻结供应商内部模型版本；审计未覆盖模型内部推理或所有供应商计费字段。
- 旧交接材料是历史快照；新规则不回写旧卡，需重新生成最新交接材料。
- 前端浏览器验收、人工语义复核和真实老人/医生试用未完成。当前仍为单人本机 MVP，不是公网多人医疗系统。

### 低心率临床暂行规则草案（待上线前医师/护士签署）

识别带有“心率、脉搏、心跳、HR”上下文且数值不高于 40 次/分或 40 bpm 的记录，加入 `low_heart_rate_candidate`、`clinical_review_required=true` 和 `clinician_or_pharmacist` 复核角色。它只表示需要专业复核的测量候选，不诊断心动过缓，不自动改药，也不单独触发急救等级。历史、转述、提问和不确定语句保留原文并进入复核，不能静默清除。若同一原文另有胸痛、呼吸困难、意识改变等现有危险描述，继续沿用现有急救规则。该草案需医师或护士确认阈值、症状组合、复测说明和展示文案后，才能作为正式医学规则。

本段是后续增补，完整流程见 [临床规则草案](CLINICAL-RULE-DRAFT.md)。候选解析要求明确指标、完整数值 `0 < 数值 <= 40` 和分钟单位；不把小数截成整数，不借呼吸频次或跨行内容作心率，也不接受秒/小时及污染单位前缀。新成功草稿保留专业复核角色，交接 `clinical_measurement_review_required` 不随记录确认清除。其余待医学核查问题分 24 类登记在 `config/clinical-review-backlog.json`，每项注明待补依据、规则评估、测试及空的专业审核字段；未添加新临床阈值到危险规则。
