# C 模块临床规则草案与待复核清单

版本：`clinical-rule-draft-v1`。编写日期：2026-09-12。状态：**AI 起草，`medical_signoff=pending`，尚无医师、护士或药师签署**。

本文按医护接诊时确认原始信息、识别需及时联系专业人员的描述、核对测量情境、转交复核的流程编写。它不是医师出具的诊疗规范，不代表临床验证完成。当前代码仍执行已有规则；本文和配套 JSON 是开发与审核材料，不直接加载到运行链路。

## 1. 第一性原则与使用边界

系统能够核实的是用户提交了什么、由谁转述、何时提交以及代码是否匹配了某种表达；系统无法独立核实症状、测量准确性或疾病诊断。患者原话、家属转述、模型草稿与医生直接证据必须保持区别。提交来源标签本身不是身份认证。

病例资料用于检查记录保真、规则行为和失败恢复。它们不授权模型诊断疾病、调整药物、确认处方或给出个体化治疗方案。模型输出与用户点击“记录准确”都不能替代专业判断，也不能清除已经保留的危险提醒。公开病例仍需保留原始来源和许可，合成材料不能标为真实患者。

未命中关键词不表示医学正常。规则匹配次数、工程测试通过率、真实模型调用成功率均不能代替临床敏感性、特异性或医疗有效性证据。

## 2. 暂行处理流程

1. **接收与保存。** 先保存完整原文及来源、记录时间，使用用户或后端已提供的发生时间；不让模型补出未经证实的时间。药名、剂量、单位、频率、否定、条件和说话人均保留在同一上下文中。
2. **本地危险描述扫描。** 不依赖网络或模型完成已有关键词与血压数字匹配。匹配成立时保留固定联系专业人员/当地急救服务的提示；不在此基础上推断具体疾病、严重程度或治疗。网络异常、输出被拒绝和用户确认均不隐藏提示。
3. **测量候选复核。** 当前低心率候选单独标记为待专业复核；与急救匹配分别记录。其余生命体征及复杂语义情境先进入开发清单，不能因为被批量扫描命中就新增患者告警、诊断或风险等级。
4. **结构整理与核对。** 模型只作现有合同允许的分类与草稿整理，摘要和引用保留整条原文。出现无法核实的信息、来源冲突或禁止的治疗行为，拒绝不合规输出并保留原文和失败状态。
5. **专业转交与追溯。** 转交材料展示原文、来源、规则版本、命中项、已有提示和待确认事项；不能把“待复核”显示为“已确诊”。新规则可以重扫旧记录，但不能悄然删除原有阳性提醒或覆盖历史证据。

测量时间、持续时间、是否复测、测量设备/部位、单位、伴随症状、是否本人/当前事件、既有诊疗意见和药物情境是供专业人员审核的信息维度。本文没有把这些维度全部变成模型可自由生成的追问，现有中性追问白名单保持有效。联系急救服务不应等待模型整理或补齐表单。

## 3. 现有规则盘点：运行有效不等于医学已签署

实际引用以 `backend/safety.py` 为准。`RULES` 含 9 类描述规则；连同单独计算的血压数字规则，一共 10 类急救匹配，全部进入临床待审清单。

| 运行规则 ID | 当前识别主题 | 上线前重点审核 |
| --- | --- | --- |
| `chest` | 胸痛、胸闷及有限口语变体 | 非急性/历史语境、否定、伴随症状与提示是否过宽或遗漏 |
| `breathing` | 呼吸困难、喘不上气等有限表达 | 用力与静息情境、持续性、口语漏项和明确否定 |
| `consciousness` | 叫不醒、意识不清等描述 | 睡眠/镇静/转述情境、发作与恢复、来源归属 |
| `convulsion` | 抽搐、全身抽动 | 肌肉跳动等相似表达、发作结束和重复发作的记录方式 |
| `bleeding` | 大量或止不住的出血描述 | 部位、持续性、主观量词、药物背景及漏报 |
| `neurologic_description` | 突发无力、口角歪、说话含糊等 | 起病时间、既往缺损、症状缓解、单侧和说话人 |
| `injury` | 摔倒和头部受伤描述 | 普通摔倒也可能命中，须审核过度提醒；兼顾头部损伤和药物背景 |
| `persistent_vomiting` | 连续、反复或停不下来的呕吐 | 已停止/跨句误联、持续时间、进食饮水和伴随描述 |
| `extreme_pressure_description` | “血压极高/极低”等主观表达 | 没有读数时的措辞、引用与否定，不把主观描述变成诊断 |
| `extreme_pressure_number` | 血压成对或高压/低压读数 | 数值边界、单位、设备、复测、症状与特殊人群；详见下段 |

血压数字代码目前沿用的工程截点是：收缩压 ≥180 或 <80、舒张压 ≥110 或 <50。列出这些数字仅用于准确描述现有实现，**不是本草案验证或推荐的临床阈值**。当前匹配器未充分解释单位、比较符、否定、历史和测量错误，必须由专业人员确认适用范围、提示方式及修改意见，再配套测试；本次不改变这些截点。

## 4. 低心率候选：不单独升级急救

运行标识为 `low_heart_rate_candidate`，复核版本以 `backend/safety.py` 的 `CLINICAL_REVIEW_VERSION` 为准。当前匹配需要同一语段内明确出现心率/脉搏/心跳/HR 标签、完整数值和分钟单位，工程候选范围为 `0 < 数值 ≤40`。**≤40 是当前工程候选截点，没有在本项目中完成医学依据审核**；它不等同于确诊心动过缓，也不表示其他数字一定安全。零值不作为可信心率读数进入此候选，仍需在数值/设备复核清单中保留问题。

候选仅要求专业复核，不单独将 `danger_detected` 设为 true，不单独把 `escalation_level` 改为 emergency，不给出停药、加药、减药或其他治疗建议。若原文同时命中既有胸痛、呼吸困难、意识改变等规则，急救提示继续由那些规则产生。

当前解析已将 `40.5` 作为完整小数处理，排除没有心率标签的“每分钟40次”，并排除每秒/每小时表达；这些属于工程边界修正，仍须持续保留回归用例。否定、历史、转述、假设和复杂比较区间的语义仍不完整，命中只能表述为“待核查线索”，不能声称是当前本人真实读数。清单必须保留这些缺口，不能把一个 ≤40 的单元测试当作整个候选规则已可靠。需核对是否本人当前读数、单位和设备、复测/持续时间、伴随症状及已知药物情况；这些都是待专业确认的上下文，不授权模型自行补全事实。

## 5. 批量待办清单与证据要求

机器可读清单为 `config/clinical-review-backlog.json`。每项均为 `needs_medical_review`；现有规则也不标为临床已通过。`priority` 是开发与审核顺序，不是患者分诊等级。`runtime_rule_ids` 只引用真实存在的运行规则，尚未实现的主题使用空数组。

`topic_patterns` 仅帮助本地离线扫描现有合成/公开测试材料，寻找值得人工查看的相关记录。命中不证明异常、规则漏报或医学事实成立；未命中也不证明数据已覆盖。扫描不得将清单内容接到生产告警、改变路由或把未引用的医学阈值加入代码。

清单同时列出每项所需的医学依据、规则修订评估和测试场景。字段 `needs_rule_update=true` 表示必须经过规则修订评估；专业审核后可以有据决定保留原实现，但不能跳过评估。`medical_sources`、`source_ids` 暂为空，`medical_reviewer` 和 `medical_review_date` 暂为 null，未编造任何来源或签名。

当前批量主题包括全部现有急救匹配、低心率候选、尚未实现的高心率/血氧/血糖/体温，以及历史、否定、主体归属、数值/单位、药物情境、测量可靠性、多症状组合、特殊人群和专业复核路由。每类均需先确认来源和适用人群，再定义阳性、阴性、边界及失败链路测试，不凭开发者经验扩大临床阈值。

上线前逐项补齐以下证据：

- 可核查的指南/共识/机构规范及具体章节、版本、发布日期、适用对象；若来源存在差异，记录取舍和范围，不用模型口述充当文献。
- 具备相应资格的审核人员姓名或内部标识、专业角色、审核日期和明确结论；药物建议范围由相应临床/药学人员确认。
- 规则适用条件、排除条件、历史/否定/转述处理、展示文案、紧急程度与复核责任；缺信息时如何提示也要确定。
- 与审核意见对应的测试及原文保真、模型失败、重启恢复、旧记录重扫、提示保留验证；实际临床性能评价单独记录，不能用软件回归数字代替。

只有对应审核证据和测试齐备，才能将相关条目签署为已审。本次文档交付不能关闭临床签署待办，也不会阻塞当前本机 MVP 保存、扫描、整理、核对、历史和交接链路。

## 6. 网络分段计时占位

`config/transport-timing.placeholder.json` 仅保留 DNS、TCP、TLS、首字节和读取阶段的未来字段。`runtime_enabled=false`、`collection=not_instrumented`，所有阶段耗时为 null。null 表示未采集，不表示 0 毫秒、网络健康或某阶段不存在；连接复用等情境未来需要单独定义。

占位文件不由运行时导入，不增加等待、重试或网络请求，不改变 API 响应结构及现有总耗时审计，不据此判断超时是网络还是模型造成。以后实现计时时再补单调时钟、阶段边界、连接复用、失败/超时及敏感信息不泄露的测试。
